# 前端开发规范

## 默认规则

- 写出用户从哪个入口执行什么操作、能看到什么结果。只承诺本次涉及的运行形态。
- 从控件追到实际数据来源。普通设置通过 Options 桥读写。桥已提供的授权数据通过桥读取，Web 服务页的后台诊断通过相对 API 读取。新增后台字段或改变配置生效时机时，追踪到实际消费方。
- 每个可见动作明确等待、成功、失败和恢复的表现。保存失败必须保留输入，允许重试。界面只能展示脱敏诊断。

## 工作流

1. 用一条状态转换描述功能。例如最近同步状态的首次读取为 `加载 → 最近成功时间 | 尚无记录 | 读取失败并可重试`。已有结果时刷新失败，同时标明数据时间和本次失败。
2. 按目标形态的数据能力安排界面。普通配置通过 Options 桥读写。最近同步状态由宿主提供脱敏数据，页面展示后台最近确认成功的时间。桌面只有普通设置和指引时，单独记录指标展示待验或待实现。涉及桥权限、服务导航或形态差异时，按[插件接入规范](../magpie-plugin-development/SKILL.md)核对目标版本。
3. 可重复刷新、切换对象或提交表单时，读取[并发交互规则](references/async-interactions.md)。后台调度由 Bun 宿主持有。
4. 用受控响应验证页面状态转换。要声称真实 Web 或桌面桥可用，必须在对应的隔离形态完成操作。记录用户看到的结果。

## 配置轮询间隔的交接示例

| 用户操作 | 页面负责的结果 | 交给下一层的内容 |
| --- | --- | --- |
| 打开配置页 | 等桥就绪，读取当前 `pollIntervalSec`，以秒显示。读失败时提示重试。 | 缺失值按已确认的配置约定处理。设计中的建议值不能直接当作读回值。 |
| 编辑并保存 | 校验输入，提交期间阻止二次写入，按目标版本的 Options 写入语义保留其他设置。写入失败后保留当前草稿。 | 将数值型 `pollIntervalSec` 交给 Options。Bun 解析器仍需独立校验外部输入。 |
| 保存返回 | 从 Options 读回并按已确认的字段语义与提交值比较。读回失败时提示“保存结果待确认”。读回值不同则保留草稿，分别显示提交值和读回值，允许重新读取，由用户决定是否再保存。 | 页面报告实际读回的值。后台是否采用该值，须观察运行任务。 |

## 输出格式

```text
入口与形态 | 用户操作 | 数据来源 | 页面结果 | 失败后的恢复操作 | 已验证范围
```

## Gotchas

- 静态页受 `connect-src 'none'` 约束。在独立浏览器标签中直接请求成功，不能作为嵌入页的通过证据。
- 读取诊断成功只表明页面取得了响应。用本次页面刷新的时间冒充后台最近成功时间，会在后台持续失败时给用户错误反馈。
