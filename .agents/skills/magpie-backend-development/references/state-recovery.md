# 持久化和跨进程接管

**读取条件**：修改持久进度、回执确认、状态版本或宿主接管。

- 变更状态结构时，从旧版本样本读取并校验，保留来源身份和已确认进度。遇到损坏或未知版本，保留原文件并返回受控恢复提示。保存时在正式文件的同一目录写临时状态文件，刷盘成功后原子替换。刷盘或替换失败时保留最近已持久化的游标。
- 处理回执时，网关客户端解码 `records[]`，按每个子批提交时的 `index` 和 `rid` 一一匹配，只接受 `accepted` 或 `skipped`。总计数相同仍可能有一项重复、一项缺失。整页待上报项均获匹配后，由拥有该轮任务的调用方提交 `next_cursor`。空页按接口返回值推进。后续子批失败、缺少回执或落盘失败时从最近一次已持久化的位置重放。
- 修改所有权时，让旧任务中止并结束在途写入，再释放状态目录锁。让新宿主取得同一把锁后读回进度。需要覆盖进程退出时，实际结束隔离旧宿主，再观察接管。
- 回执场景在“中心已接收、本地尚未保存”处中断。验证重放的 ID 稳定，每个预期 `rid` 最终恰有一条记录，相关总数等于不同预期 `rid` 的数量，全部确认后才推进。重载场景在旧请求未完成时触发，观察旧任务的迟到结果不能写回。
- 需要承诺设备掉电恢复时，核实目标操作系统和文件系统对数据及目录项的持久化保证，再对相应条件取证。只中断进程的演练只能支持进程中断恢复结论。
