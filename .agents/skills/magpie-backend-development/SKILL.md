# 后端开发规范

## 默认规则

- 从实际入口追到首个可观察结果，明确调用方依赖的输入、输出与失败行为。纯映射可在输出对象处结束追踪。
- 在每个发生副作用的边界标出执行者、成功条件、失败后保留的状态。复用已有 I/O 接口，只在需要控制时间、请求或写入时增加可替换边界。
- 使用公开网关接口。后台发送与源端模型调用必须独立。按角色分离凭据，HTTPS 必须校验证书，禁止将上报凭据转发给重定向目标。

## 工作流

1. 用一行列出此次改动经过的路径，并指出谁能提交最终结果。首版可按以下职责组织，具体路径随实现确定。

   | 职责 | 输入、依赖与输出 |
   | --- | --- |
   | 宿主入口与配置解析 | 入口接收 Options，交给解析器校验，向后台任务传递有效配置并管理任务所有权。无效配置返回受控诊断，不用它启动轮询。 |
   | 后台任务 | 按有效间隔调度一轮读取、上报、确认和保存。任务调用网关客户端和状态存储，协调失败、取消及重试。 |
   | 源端与中心客户端 | 源端客户端从本机回环读取一页，返回记录及不透明的续读游标。中心客户端按白名单发送映射后的记录并解码逐项回执。两者都把结果交回当前任务。 |
   | 状态存储 | 从插件专用目录读回身份和进度，仅按当前任务的提交决定持久化新进度。分别保存最近尝试与最近确认时间，失败尝试不能刷新最近成功时间。宿主诊断入口从中选取可展示的字段。 |
2. 改 HTTP 行为时，明确超时、取消和响应判定。限流或网络中断可退避重试。凭据无效应阻塞并返回需修复的类别。重试必须复用原来源身份。
3. 改持久状态、回执推进、跨进程接管或旧状态兼容时，读取[持久化与接管规则](references/state-recovery.md)。改变中心目标或已有进度的回填边界时，先确认目标和历史范围。
4. 对每个修改的边界构造一个能区分正确与错误实现的观察点。纯字段映射验证实际消费者。回执与落盘使用模拟中心和临时状态。宿主重载在单个隔离实例观察新旧任务的写入权。

**修改 `pollIntervalSec` 时**，先确认字段的类型、秒单位、有效范围和缺失策略。将有效值传到已有调度器，在可控时间下检查下轮运行采用的新间隔。配置校验失败时不得把无效值交给计时器。若还要证明保存 Options 会触发新配置生效，由[插件接入规范](../magpie-plugin-development/SKILL.md)追踪实际宿主通知或重载，并观察下一轮任务。实现接口时同时采用[后端代码规范](../magpie-backend-code-style/SKILL.md)。

## 输出格式

```text
入口及调用方 | 成功后的可观察结果 | 失败后保留什么 | 重试或恢复的证据
```

## Gotchas

- HTTP `2xx` 不能证明页内所有记录均已确认。涉及游标推进时必须检查业务回执。
- 取消计时器不会自动撤回在途请求。释放锁前确认旧任务已丧失写入能力。
