# 项目文档更新规范

## 默认规则

- 先写出受影响的读者和要完成的操作。同一行为在一处维护详细说明，其他读者入口按需链接过去。
- 文案必须区分设计约定、已实现行为和已验证的运行形态。例子使用合成数据。功能与相应说明在同一任务交付。

## 工作流

1. 按读者的问题选一处主说明。只改措辞或内部函数时，核对受影响的事实和入口即可。

   | 读者需要做什么 | 主说明 | 写入前核对什么 |
   | --- | --- | --- |
   | 找到功能与实现入口 | [功能规格](../../../docs/01-插件定位与功能规格.md)、[整体架构](../../../docs/03-整体架构与模块职责.md) | 当前阶段、受影响的使用者和模块职责。首页链接到主说明。 |
   | 核对宿主或协议 | [开发基线](../../../docs/02-开发基线与兼容性.md)、[网关接口](../../../docs/04-网关接口与用量数据规范.md) | 目标版本、字段、权限和回执语义。 |
   | 追踪进度或处理故障 | [同步与恢复](../../../docs/05-同步流程与故障恢复设计.md) | 整页提交条件、可重放范围和持久化结果。 |
   | 新增配置项或修改页面 | [配置与诊断](../../../docs/06-配置与诊断页面设计.md) | 读者如何设置，单位、建议值、实际默认值、生效时机及 Web、桌面差异。 |
   | 搭环境、接入中心或复验产品 | [插件开发指南](../../../docs/Magpie插件开发指南.md)、[部署与运维](../../../docs/07-部署接入与运行维护.md)、[阶段与验收](../../../docs/08-开发阶段与验收计划.md) | 分别核对隔离示例步骤、实际运行形态，以及产品已有证据和待验项。 |

2. 例如补充 `pollIntervalSec` 时，从解析端核实名称、秒单位、范围和缺省行为，从调度器及目标宿主证据核实生效时机。设计中的 60 秒建议值应标为建议值。仅验证保存和读回时，文案可说明“已保存”，生效条件留待验证后补齐。
3. 本地 Markdown 文件链接有增删、移动或重命名时，用[链接检查脚本](scripts/check_local_links.py)检查受影响的文档及已知引用方。项目根目录下的示例命令如下。需要 `uv`，它会按脚本声明准备 Python 和 Markdown 解析器；已有匹配环境也可直接用 Python 执行。

   ```powershell
   uv run --script .agents/skills/magpie-docs-update/scripts/check_local_links.py --root . README.md
   ```

4. 处理脚本报告的缺失文件。新增章节锚点还须单独核对目标标题，新增命令须核对实际参数。纯措辞变更在受影响事实与入口通过 L0 后停止。

## 输出格式

`读者和操作 | 已更新的主说明 | 支持该说法的证据 | 待验项`。内部变更可直接给出说明仍准确的理由。

## Gotchas

- 手册写“已支持”之前核对对应形态的证据。临时 CLI 能加载不能证明 Web 交互、桌面或无人值守运行正常。
- 相对链接以包含该链接的文档目录为基准。脚本检查 Markdown 文件目标是否存在，标题锚点、外部 URL 和 HTML 标签需按改动另外检查。
