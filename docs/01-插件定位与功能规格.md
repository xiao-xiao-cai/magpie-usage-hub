# 插件定位与功能规格

Magpie Usage Hub 面向同时使用多台 Magpie 的管理员。Windows Magpie 将模型用量通过原生 OTLP 发送到 Docker 中心，管理员在中心 Magpie Web 按来源、时段和模型查询汇总、趋势与明细。中心本机用量由插件从回环网关自动采集。

`0.7.0` 是原生 OTLP 接入候选，插件安装后默认停用，源码和验收基线为 Magpie `v0.1.4799`。[开发基线](02-开发基线与兼容性.md) · [原生 OTLP 接入验收](08-开发阶段与验收计划.md#原生-otlp-接入验收)

## 谁需要部署什么

| 参与方 | 部署和使用方式 | 可以看到什么 |
| --- | --- | --- |
| Docker 中心 | 安装 Usage Hub，在插件页启用 OTLP 接收与看板，通过 Web 登记来源。 | 查中心本机和各来源的用量，并核对每个 OTLP 来源的最近接收时间。 |
| Windows 来源 | 本机网关保持回环。在原生 Magpie 的可观测性设置开启 OTLP，使用该来源的令牌经 WireGuard 发送仅含元数据的 Trace。 | 在中心核对首次接收和新调用明细。 |

## 主动上报与明细查询

| 功能 | 触发与执行方 | 用户可观察的结果与验收依据 |
| --- | --- | --- |
| 登记与维护来源 | 管理员在中心 Web 保存来源名称和令牌的 SHA-256 摘要，Windows 导出请求使用对应令牌。 | 同一来源可暂停、恢复、轮换或撤销凭据。首次接收有效用量后显示「已收到用量」和「最近接收」。[来源管理](06-配置与诊断页面设计.md#来源管理) |
| 接收新增用量 | Windows 在开启导出后产生新的网关尝试或会话生成，中心按已认证来源提交收到的事件。 | 已保存的记录在来源离线期间仍可查。批次若在有限重试内送达，按原调用时间入账。超出重试或内存队列范围的事件可能缺失。[故障恢复](05-同步流程与故障恢复设计.md) |
| 查询时段及明细 | 管理员按时间范围、来源、模型和用量分项筛选。 | 默认近 7 天，另有今天、近 30 天及自定义区间。可查看逐来源总量、小时或日趋势、模型用量和分页明细。[统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计) |
| 核对来源状态 | 管理员打开看板或来源详情。 | OTLP 来源显示接收状态，历史来源保留可查询数据，中心本机显示游标采集进度。覆盖区间取已发布数据的最早及最晚原调用时间。[配置与诊断](06-配置与诊断页面设计.md) |

Windows 在 09:59:59 产生的用量若在 10:00:05 接收成功，记录仍计入 09 时段。OTLP 的调用数按收到的网关尝试和会话生成计，同一次业务调用可能出现在两个分项；中心本机和已迁移的历史来源沿用原生账本请求口径。对账时使用同一时间范围并逐来源比较。[时间与计量口径](04-网关接口与用量数据规范.md#怎样解释中心统计)
