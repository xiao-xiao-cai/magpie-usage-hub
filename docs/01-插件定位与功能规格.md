# 插件定位与功能规格

Magpie Usage Hub 面向同时使用本机网关和中心网关的用户。来源电脑继续用自己的供应商调用模型，发送插件把已经记账的本机用量异步汇入中心。中心 Web 看板把中心本机记账与各来源上报分开呈现，并提供合计。

**当前阶段** `0.3.0` 已验收多来源原生上报、Web 诊断和原中心回填。`0.4.0` 为预览版，默认停用。托管试用由中心登记来源与采集范围，节点配对后从独立 `now` 游标主动上报。[开发基线](02-开发基线与兼容性.md) · [开发阶段与验收计划](08-开发阶段与验收计划.md)

## 谁需要部署什么

| 参与方 | 部署和使用方式 | 可以看到什么 |
| --- | --- | --- |
| 有独立 Magpie 的来源电脑 | 安装发送插件并使用一次性配对码加入中心。模型照常发往本机配置的供应商。 | 本机原生用量页显示本机账本，插件页提供节点配置与同步诊断。 |
| 中心 Magpie | 安装中心角色，通过 Web 管理试用来源和接收上报。通过原生网关为直接接入的设备提供模型服务。 | 原生用量页查询中心历史，插件看板呈现本机、各来源和合计。 |
| 直接调用中心的设备 | 配置中心网关和该设备的模型 Key，中心直接记账。 | 中心可用相应的 `callerKey` 追查直接调用。 |
| 可信业务后端 | 使用专用只读 Key 查询中心原生网关，按业务刷新周期取数。 | 可查原生账本的汇总与明细；插件账本通过管理员 Web 看板核对。 |

## 首版应该交付的功能

| 功能 | 触发与执行方 | 用户可观察的结果与验收依据 |
| --- | --- | --- |
| 采集本机网关用量 | 源端宿主轮询公开回环接口，按中心指定的专用模型 Key 与供应商 ID 筛选本机计量尝试。 | 例如专用 Key 转到另一个供应商的记录，不属于此来源的采集范围。见[数据范围](04-网关接口与用量数据规范.md)。 |
| 配对并选择采集起点 | 管理员创建托管来源，节点启用后兑换配对码并首次持久化 `now` 游标。 | 本地诊断可核对游标就绪，后续只采游标之后的匹配用量。旧版 Options 支持从 `now` 或可见历史 `start` 起步。见[同步流程](05-同步流程与故障恢复设计.md)。 |
| 增量分批发送 | Bun 后台按已确认游标取页，拆批上报，核对整页回执后保存进度。 | 中心停机时本机模型请求仍可完成。中心恢复后补齐源账本仍可见的记录。见[隔离验收](08-开发阶段与验收计划.md)。 |
| 管理多台来源 | 管理员在中心 Web 创建具名来源，选择启用或暂停并设置轮询间隔。节点保存专属凭据与来源 UUID。 | 可查看最近联系和最近接收入账，暂停期间保留已确认游标，恢复后按原身份续传。采集范围变化时创建新来源并建立新游标。见[来源管理](06-配置与诊断页面设计.md#来源管理)。 |
| 安全重放 | 请求超时、进程重启或后续子批失败，源端从已确认位置重读。 | 同一来源的同一行重传后，中心只保留一条。见[故障恢复](05-同步流程与故障恢复设计.md)。 |
| 配置与诊断 | 操作者通过 Options 设置角色和网络入口，通过 Web 核对宿主状态。 | 能区分设置已保存、节点已联系中心、整页已确认及需要处理的故障。见[页面设计](06-配置与诊断页面设计.md)。 |
| 恢复原中心的用量 | 使用连续同步配置的来源遇到游标失效或原中心历史缺口时，操作者核对原绑定与历史范围后提交回填。 | 原来源沿用身份回填。已确认记录可按 `rid` 对账，剩余缺口依赖可读的源账本或备份。见[运行维护](07-部署接入与运行维护.md)。 |
| 核对独立账本 | 管理员从中心插件页打开 Web 看板，选择今天、近 7 天或近 30 天。 | 本机和各来源分别显示计量尝试、Token、估算费用与分页明细。任一账本读取失败时，合计暂不可用。见[中心 Web 用量看板](06-配置与诊断页面设计.md#中心-web-用量看板)。 |

看板的中心本机部分读取原生 `through` 和 `direct`，来源部分读取 Hub SQLite。旧原生 `reported` 与 Hub 上报属于不同账本。实时限流、路由、预算与供应商配额按各网关的实际调用执行。同一供应商账号的实际账单仍以供应商计量为准。
