# 插件定位与功能规格

Magpie Usage Hub 面向同时使用本机网关和中心网关的用户。来源电脑继续用自己的供应商调用模型，发送插件把已经记账的本机用量异步汇入中心。用户在中心原生用量页看两条路径的历史，业务后端通过只读 API 取数。

**当前阶段**已验收单条用量链路。操作者选定一条源端测试调用，由发送插件读取并上报，随后通过中心只读 API 对账。下表为首版交付要求。[开发基线](02-开发基线与兼容性.md) · [开发阶段与验收计划](08-开发阶段与验收计划.md)

## 谁需要部署什么

| 参与方 | 部署和使用方式 | 可以看到什么 |
| --- | --- | --- |
| 有独立 Magpie 的来源电脑 | 安装发送插件，分配独立来源身份及上报凭据。模型照常发往本机配置的供应商。 | 本机原生用量页显示本机账本，插件页提供该来源的配置与诊断。 |
| 中心 Magpie | 用原生网关接收上报，同时为直接接入的设备提供模型服务。 | 原生账本和用量页统一呈现中心调用与已接收的历史上报。 |
| 直接调用中心的设备 | 配置中心网关和该设备的模型 Key，中心直接记账。 | 中心可用相应的 `callerKey` 追查直接调用。 |
| 可信业务后端 | 使用专用只读 Key 查询中心，按业务刷新周期取数。 | 汇总反映已入账的记录，明细可按模型、日期及来源类别筛选。 |

## 首版应该交付的功能

| 功能 | 触发与执行方 | 用户可观察的结果与验收依据 |
| --- | --- | --- |
| 采集本机网关用量 | 源端宿主轮询公开回环接口，筛选本机处理且已记账的模型调用。 | 本机调用出现在中心的上报明细，导入、跨机共享和已由中心记账的中转调用排除。见[数据范围](04-网关接口与用量数据规范.md)。 |
| 选择采集起点 | 首次启用时，操作者选择 `now` 从当前进度开始或 `start` 扫描可见历史。 | 两种模式的首次游标及后续新增记录可核对。见[同步流程](05-同步流程与故障恢复设计.md)。 |
| 增量分批发送 | Bun 后台按已确认游标取页，拆批上报，核对整页回执后保存进度。 | 中心停机时本机模型请求仍可完成。中心恢复后补齐源账本仍可见的记录。见[隔离验收](08-开发阶段与验收计划.md)。 |
| 区分多台来源 | 每个源实例持久保存自己的 `sourceId`，独立配置上报 Key。 | 重启后来源稳定，两台机器的上报可按明细 `rid` 追查。见[字段映射](04-网关接口与用量数据规范.md)。 |
| 安全重放 | 请求超时、进程重启或后续子批失败，源端从已确认位置重读。 | 同一来源的同一行重传后，中心只保留一条。见[故障恢复](05-同步流程与故障恢复设计.md)。 |
| 配置与诊断 | 操作者通过 Options 设置目标、凭据文件和采集策略，按 Web 或桌面能力查看状态。 | 能区分保存、正在尝试、整页已确认、退避和需要处理的阻塞。见[页面设计](06-配置与诊断页面设计.md)。 |
| 显式恢复与回填 | 游标失效、中心切换或恢复旧备份时，操作者核对目标与历史范围。 | 原来源沿用身份回填。完成后可对账，仍有缺口时可追查源账本或备份。见[运行维护](07-部署接入与运行维护.md)。 |

中心直接处理的记录归 `through`，插件追加的记录归 `reported`。上报参与历史用量和估算费用统计。实时限流、路由、预算与供应商配额按各网关的实际调用执行。同一供应商账号的实际账单仍以供应商计量为准。
