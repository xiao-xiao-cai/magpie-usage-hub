# 部署接入与运行维护

以下步骤对应中心只读拉取的 `0.5.0` 候选。中心使用服务器已有的 Docker Magpie，远程来源使用原生网关。实机安装、共享设置、凭据签发、合成流量与切换安排在获准的维护窗口。[第六阶段验收](08-开发阶段与验收计划.md#第六阶段中心只读拉取验收)

## 核对网关、网络和凭据

| 在哪里 | 核对或操作 | 成功信号 |
| --- | --- | --- |
| 中心容器 | 到 `/opt/magpie` 确认实际 Compose 服务、配置挂载和原生网关端口，从容器内核对 `magpie --version` 及宿主 Bun 版本。通常用 `http://127.0.0.1:3425` 访问本机网关。 | 回环的原生用量请求返回 `200` 与所选周期的两类本机汇总。 |
| Windows Magpie | 在「设置 → 网络与共享」开启局域网共享。按实际来访地址限制 Magpie 放行范围和 Windows 防火墙，通常为中心服务器的 WireGuard 地址。签发专用只读 Key，模型、账户和预算限制留空。 | 从中心容器能访问 Windows 的 WireGuard 网关并用该 Key 读取相同周期。本机客户端仍可通过 `127.0.0.1:3425` 调用。 |
| 中心 Web | 从已登录的 Magpie Web 进入插件。页面服务 `3493` 保持回环监听，由 Magpie Web 代理。 | Options 页和用量看板均能从管理入口打开。 |

从中心容器验证路由与实际来访地址。Windows 来源地址取其原生网关的根地址，如 `http://<Windows-WireGuard-IP>:3425`。`3430` 是中心 Magpie Web 的管理入口。若来源用 `MAGPIE_ADDR` 显式固定回环，先核对本机调用依赖和共享监听行为，再在维护窗口调整。用 HTTP 时限定在回环或 WireGuard 内，HTTPS 校验服务端证书。[共享监听](https://github.com/yetone/magpie/blob/v0.1.4874/docs/reference.md#L941-L958) · [来源地址限制](https://github.com/yetone/magpie/blob/v0.1.4874/docs/reference.md#L1009-L1020)

在 Windows 来源的凭据管理中选择只读，或在该来源的终端执行 `magpie gateway-key add "Usage Hub" --read-only`。只读资格由来源签发时的设置保证。将签发结果通过管理页提交给中心，凭据留在受控的传递和存储路径中。[Magpie 只读 Key](https://github.com/yetone/magpie/blob/v0.1.4874/docs/subsystems/gateway-routing.md#L1825-L1835)

## 安装候选并登记来源

1. 在中心宿主机核对候选归档 SHA-256，将候选解包到 Magpie 配置卷内可长期读取的目录。在中心容器使用 `magpie plugin add <容器内的包根目录>` 注册包，并核对 CLI 加载结果。实际 Web 查询另从登录入口检查。[安装说明](../README.md#安装插件包) · [候选包核对](GitHub开源准备.md#核对公开资料与产物)
2. 打开中心插件页，确认容器内回环网关根地址，显式启用并保存 `collectionMode: "pull"`。进入 Web 看板，按所选周期核对中心本机汇总。[Options 字段](06-配置与诊断页面设计.md#options-与宿主校验)
3. 打开「来源管理」，输入远程实例名称、网关根地址与专用只读 Key。点击「测试连接」，确认通过后保存并启用。回到看板刷新，按同一周期与 Windows 原生汇总对账。[来源管理](06-配置与诊断页面设计.md#来源管理) · [统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计)

## 日常维护

- **来源不可用。** 可继续查询同一看板中的其他来源。从容器检查 WireGuard 路由、原生网关端口、允许地址和 Key。修复后刷新，从各来源账本读取当期可见数据。[故障处理](05-同步流程与故障恢复设计.md#故障处理)
- **轮换 Key。** 在来源签发新的专用只读 Key，中心来源管理填入、测试并保存。在看板确认新 Key 可用后，按维护流程撤销旧 Key。该来源的 ID 和名称沿用原值。
- **配置和备份。** 中心将来源和 Key 保存在 `<Magpie 配置目录>/magpie-usage-hub/pull/sources.json`。限制宿主文件及备份的访问权限。恢复来源配置前先停用中心，等当前宿主退出，再恢复同一状态目录。启用后重做连接测试并按周期核对看板。

## 升级与回退

1. **备份旧接入。** 升级前备份两端插件版本、Options 和状态卷，记录正在使用的旧发送、上报凭据和 `3494` 映射。原生账本由各自 Magpie 管理，旧中心账本与 `pull/` 配置保存在独立目录。[`v0.4.0` 部署及备份说明](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/v0.4.0/docs/07-部署接入与运行维护.md#备份恢复和升级)
2. **启用中心拉取。** 旧启用配置会提示迁移。按上节显式保存并启用 `pull`，在管理页接入远程只读来源，分别核对本机和远程汇总。双端验收通过后，在维护窗口停用旧发送任务。确认旧任务退出后撤下旧接收映射及对应上报凭据，旧账本纳入备份。
3. **回退验证。** 停用中心拉取并确认宿主退出。恢复固定 `v0.4.0` 包、其 Options、所需接收端口和凭据，再恢复实际使用的旧任务和原状态目录。验证原生网关及旧插件链路。切换窗口内的原生用量仍由原实例持有。[`v0.4.0` 归档](https://github.com/xiao-xiao-cai/magpie-usage-hub/releases/tag/v0.4.0) · [`v0.4.0` 试用接入与回退](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/v0.4.0/docs/07-部署接入与运行维护.md#第五阶段试用接入)
