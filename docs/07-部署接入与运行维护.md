# 部署接入与运行维护

在服务器的 Docker Magpie 安装 Usage Hub `0.7.0`。Windows 运行原生 Magpie，使用内置可观测性设置经 WireGuard 上报。以下以 Magpie `v0.1.4799` 为基线。[原生 OTLP 验收](08-开发阶段与验收计划.md#原生-otlp-接入验收)

## 中心安装与接收

1. 确认 Compose 服务、Magpie 配置卷和容器内 `magpie --version`。从仓库根目录运行 `npm pack --ignore-scripts` 生成 `magpie-usage-hub-0.7.0.tgz`。在持久卷解包，在中心容器运行 `magpie plugin add /config/plugins/usage-hub/package`，路径换成实际包含 `package.json` 的目录。既有部署先按[升级与回退](#升级与回退)保留备份。
2. 在中心 Magpie Web 的 **Magpie Usage Hub** 打开「中心设置」。确认「中心本机网关」为该容器内的回环根地址，通常是 `http://127.0.0.1:3425`。「OTLP 接收端口」默认 `3494`，看板时区默认 `Asia/Shanghai`。[设置字段](06-配置与诊断页面设计.md#options-与宿主校验)
3. Docker 桥接模式填写「OTLP 监听地址」`0.0.0.0`，并在 Compose 中将端口**仅发布到服务器的 WireGuard 地址**。将示例 `192.0.2.2` 换成实际地址。宿主网络模式直接监听实际 WireGuard 地址。按 Docker 的端口转发路径限制入接口及已登记对端的地址，确认公网和未登记的网络路径无法访问。`3493` 页面服务通过已登录的 Magpie Web 代理访问。下例使用 WireGuard 隧道内的 HTTP，使用 HTTPS 时由反向代理终止 TLS，Windows Magpie 校验证书和主机名。[端口职责](03-整体架构与模块职责.md)

   ```yaml
   ports:
     - "192.0.2.2:3494:3494/tcp"
   ```

4. 勾选「启用 OTLP 接收与看板」并「保存设置」。从同一 Magpie Web 打开「打开用量看板」，确认后台采用新修订并看到「中心本机」。生产网络切换时先完成来源登记，再启用 Windows 导出。[配置与诊断](06-配置与诊断页面设计.md)

## Windows 上报配置

1. 接通 WireGuard，在 PowerShell 运行 `Test-NetConnection -ComputerName 192.0.2.2 -Port 3494`，换成实际中心地址和端口。`TcpTestSucceeded` 应为 `True`。Windows Magpie 网关继续使用本机回环，例如 `127.0.0.1:3425`。若 Windows 管理了出站白名单，放行至中心的这一条地址和端口即可。
2. 每台设备生成独立的 32 字节随机令牌。在同一个 PowerShell 会话执行以下命令。将输出的 SHA-256 摘要填入**中心**用量看板的「来源管理 → 添加 OTLP 来源」，输入来源名称，点击「保存来源」。

   ```powershell
   $usageHubBytes = New-Object byte[] 32
   $usageHubRandom = [Security.Cryptography.RandomNumberGenerator]::Create()
   try { $usageHubRandom.GetBytes($usageHubBytes) } finally { $usageHubRandom.Dispose() }
   $usageHubToken = [BitConverter]::ToString($usageHubBytes).Replace('-', '').ToLowerInvariant()
   $usageHubHash = [Security.Cryptography.SHA256]::Create()
   try {
       $usageHubDigest = [BitConverter]::ToString($usageHubHash.ComputeHash([Text.Encoding]::ASCII.GetBytes($usageHubToken)))
   } finally { $usageHubHash.Dispose() }
   $usageHubDigest.Replace('-', '').ToLowerInvariant()
   ```

3. 在 **Windows Magpie** 打开「设置 → 可观测性（Observability）」，按下表填写。将以下命令生成的请求头粘贴到 `OTLP headers`，确认保存后开启 `OTLP export`。Magpie 会在基础地址后追加 `/v1/traces`。[原生设置与环境变量](https://github.com/yetone/magpie/blob/v0.1.4799/docs/reference.md#L4397-L4421)

   ```powershell
   "Authorization=Bearer%20$usageHubToken" | Set-Clipboard
   ```

   | Magpie 字段 | 取值 |
   | --- | --- |
   | `Collector` | `OTLP`。 |
   | `OTLP endpoint` | 中心接收基础地址，例如 `http://192.0.2.2:3494`。 |
   | `OTLP headers` | `Authorization=Bearer%20<本机令牌>`。中心登记的是摘要。 |
   | `Export metrics` | `Off`。本实现接收逐条 trace。 |
   | `Request and response content` | `Metadata only`。 |
   | `Trace agent conversations` | 需要受支持的本机会话用量时开启。会话与网关各自有覆盖范围，查询可按分项筛选。 |

4. 保持 Windows Magpie 及本机网关运行。让网关处理一条新请求，再在中心看板刷新该来源。「等待首次上报」变成「已收到用量」，「最近接收」显示时间，明细显示调用时的模型和 Token。要验证会话分项，允许 Magpie 读取对应客户端的本机会话，再完成一条新调用。例如 Codex 可执行 `magpie sessions read on codex` 后查看「OTLP 会话」。[原生会话覆盖](https://github.com/yetone/magpie/blob/v0.1.4799/docs/reference.md#L4488-L4529) · [统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计)

Windows 原生导出会重试部分失败，成功送达的迟到记录按原调用时间入桶。启用前的记录、队列溢出或重试耗尽的批次不会自动补齐。中心保留已入库历史。[原生导出队列与失败处理](https://github.com/yetone/magpie/blob/v0.1.4799/docs/reference.md#L4593-L4605) · [故障处理](05-同步流程与故障恢复设计.md#故障处理)

## 日常维护

- **连接排查。** TCP 不通时检查 WireGuard、Compose 发布、中心监听和实际转发链的防火墙。TCP 正常时，检查 Windows Magpie 的 OTLP 开关和 endpoint，核对请求头里的令牌与中心登记的摘要，确认来源已启用。一次完整验证以中心出现本次新调用为准。
- **令牌轮换。** 在中心为原来源登记新摘要，在 Windows 更新 `OTLP headers`。完成一条新调用，中心显示新凭据已验证后撤销旧凭据，历史仍归同一来源。[来源管理](06-配置与诊断页面设计.md#来源管理)
- **中心备份。** 数据库位于 `<Magpie 配置目录>/magpie-usage-hub/push/center.sqlite`。采用 SQLite 一致性备份，或停写后备份整个状态卷。恢复时核对备份点之后的凭据撤销及轮换记录，再恢复接收。备份点之后仅在中心存在的 OTLP 历史不会由发送端自动重放。[故障处理](05-同步流程与故障恢复设计.md#故障处理)

## 升级与回退

1. 在维护窗口保存旧包、Options、中心状态卷和实际防火墙规则，停止旧实例的采集或接收。曾在 Windows 启用旧版 Usage Hub 上报时，先停用该插件。`0.6.0` 的中心本机游标和已发布的远程历史随 SQLite schema 升级保留。`0.5.0` 的 `pull/` 配置和 `v0.4.0` 的账本仍在各自的路径。[旧版本接入说明](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/32abba84584f302168f42facd84cf126cea69387/docs/07-部署接入与运行维护.md)
2. 在中心容器用 `magpie plugin list --json` 核对 Usage Hub 已注册的 `spec`。旧插件使用本地目录且沿用路径时，在停写后把该目录整体换成新包的 `package/` 内容，再用同一个路径执行 `magpie plugin add`，保留原 Options。改用新路径或从 npm 注册切换时，记录原设置，用 `magpie plugin rm "<旧 spec>"` 移除旧注册，再按[中心安装与接收](#中心安装与接收)注册新目录，重新保存中心设置。两种方式都沿用原状态卷。
3. 按上文为 Windows 原生 OTLP 登记新来源，记录切换时间。旧历史继续按原来源查询，交叉时段按来源独立核对。验证 Windows 的 Magpie 回环和到中心 `3494` 的出站。若曾为中心拉取增加 Windows `3425` 的项目专用入站规则，按备份恢复此前的入站状态，验证中心至 Windows `3425` 的项目访问已关闭。
4. 回退前暂停接收并备份新版库。停用新版宿主，恢复旧包、原插件注册、对应的 Options、网络规则和升级前的数据库快照。改过注册路径时，从备份恢复旧注册，或按记录移除新版 `spec` 后重新添加旧 `spec`。保留新版备份以追溯切换后收妥的 OTLP 用量。[恢复与备份](05-同步流程与故障恢复设计.md#故障处理)
