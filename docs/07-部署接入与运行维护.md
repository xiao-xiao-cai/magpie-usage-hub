# 部署接入与运行维护

本页供中心运维、来源端管理员和业务后端开发者使用。发送插件处于设计阶段。以下接入步骤适用于已经按[验收计划](08-开发阶段与验收计划.md)在隔离环境验证的安装包。准备 Windows 配置、回环端口和本地包时，见[Magpie 插件开发指南](Magpie插件开发指南.md)。

## 准备中心和凭据

1. 固定已验收的 Magpie 版本，配置供应商并验证一台直接接入的设备可使用模型。Docker 持久化整个 `/config`。其他运行方式备份实际数据目录。每个独立网关使用独立数据目录，避免多个进程并发写同一账本。
2. 使用已有私网或配置 HTTPS。原生 TLS 命令为 `magpie serve --tls-cert <证书链路径> --tls-key <私钥路径>`，容器可配置 `MAGPIE_TLS_CERT`、`MAGPIE_TLS_KEY`。管理 Web 限制到管理网络或回环。使用 HTTPS 代理时核对转发配置，实际验证未经授权的连接仍被拒绝，且无法绕过代理限制直达后端。
3. 分配下表各角色的凭据，再从业务后端所在网络验证其可见范围。上报 Key 通过受保护文件交给来源宿主，示例和验收使用隔离凭据。

| 持有方 | 权限与配置 | 接入检查 |
| --- | --- | --- |
| 每台发送来源 | 分配各自的上报 Key。远端写入要求可写且未受预算、模型或账号范围限制。该 Key 同时有模型调用等网关能力。 | 优先用私网或限制来源地址。若代理限制该入口只可 `POST /v1/magpie/usage/requests`，同时封住直连旁路，验证该凭据经此入口无法调用模型。 |
| 可信业务后端 | 单独创建只读 Key，例如 `magpie gateway-key add usage-business --read-only`。可读取全局用量。 | 验证能查询，写入与模型调用被拒绝。 |
| 直接使用中心的设备 | 每台配置普通模型网关 Key。 | 测试调用在中心归为 `through`，可按该 Key 归属查看。 |
| 管理员 | 使用独立管理凭据访问管理入口，处理配置变更、授权和回填。 | 限定访问范围，发送请求和业务查询各用自己的凭据。 |

## 接入第一台来源和后续设备

1. 检查本机原生页有本机网关调用，在回环读 `cursor=now` 核对游标响应。确认该源的用量共享和中转路由符合[采集范围](04-网关接口与用量数据规范.md)。
2. 从 Magpie 插件页安装已验证的包，或运行 `magpie plugin add <插件包目录>`。通过 Options 配置来源、中心、凭据文件路径和首次模式。先用 `now` 把后续一次调用与历史分开观察。
3. 打开插件页查看启动状态，在来源端使用合成输入完成一条可计量的模型调用。通过中心只读明细找到 `reported` 行，核对 `rid`、原调用时间、模型、Token 和状态。同时检查直接调用中心的设备产生 `through` 行。
4. 按支持范围验收断网、重复回填和重启。补历史前确认边界。下一台有独立网关的来源分配新 `sourceId`、上报 Key 与状态目录。只使用中心网关的设备配置模型 Key 即可。

## 业务后端查询示例

业务后端注入 `MAGPIE_CENTRAL_URL` 和 `MAGPIE_USAGE_READ_KEY`。以下 PowerShell 请求读取中心全部可见历史的汇总与上报明细第一页，遇到重定向即停止。

```powershell
$magpieCentral = $env:MAGPIE_CENTRAL_URL.TrimEnd('/')
$usageHeaders = @{ Authorization = "Bearer $env:MAGPIE_USAGE_READ_KEY" }
$usageSummary = Invoke-RestMethod -Uri "$magpieCentral/v1/magpie/usage?period=all" -Headers $usageHeaders -MaximumRedirection 0
$reportedPage = Invoke-RestMethod -Uri "$magpieCentral/v1/magpie/usage/requests?period=all&via=reported&limit=100&offset=0" -Headers $usageHeaders -MaximumRedirection 0
```

业务看板从汇总 API 读取总量，钻取用 `day`、`agent`、`provider`、`model`、`callerKey` 和 `via` 等明细条件。按 offset 查看时每页最多 500 行，持续写入期间页位置可能移动。需要持续导出时用中心游标逐页读取。自然日对账先统一时间边界。查询只反映中心已经接收的数据。[查询协议与统计口径](04-网关接口与用量数据规范.md)

## Windows 登录、重载和休眠恢复

`magpie autostart on` 会在 Windows 登录后启动 Magpie。是否同时启动发送任务，须在该来源实际使用的宿主形态验证。登录后保持插件页关闭，走平常的模型调用路径，在中心检查新 `reported` 行。安装、改配置、升级重载及睡眠恢复后分别确认后台恢复，且同一来源仅一个任务写入进度。

要求无人值守且已有本机 Magpie Web 管理入口的来源，可在隔离环境验证 Windows 任务计划程序能否唤醒宿主。计划任务在登录后及定期执行时，使用管理鉴权读取 `GET /api/plugin-pages`，找到本插件当次 `url`，校验为回环同源后 GET 该页面。唤醒后仍由 Bun 持有发送循环。管理路由有固定版本源码依据，计划任务与实际运行形态的兼容性待验。[宿主启动路径](https://github.com/yetone/magpie/blob/v0.1.4783/internal/gui/pluginpage.go)

仅有桌面入口且尚未验证自动唤醒时，按登录后手动打开一次插件页使用。要求无人值守的部署须在关页、重启和掉线恢复均通过验收后启用。

## 备份、恢复和升级

| 运维场景 | 操作及对账依据 |
| --- | --- |
| 日常保留 | 原生 `usage.jsonl` 按行追加，账本可用于重建上报去重索引。默认 30 天查询窗口、约 30 天的删除标记、约 90 天的内置共享窗口各有用途。`period=all` 的范围由实际保留、清除和备份决定。观察账本与变更日志空间、游标扫描及索引重建耗时，必要时调整轮询周期与单轮预算。 |
| 备份或迁机 | 定期备份中心 `/config` 或实际数据目录。来源端备份账本、插件身份及已确认进度，凭据文件分开保护。原实例迁移前停止旧发送者，再沿用身份。并行增加的新机器生成独立身份。 |
| 中心恢复旧备份 | 暂停各来源，核对备份截至时间、可能缺失的来源及历史范围。保持原 `sourceId` 回填，分别抽查缺口已补齐和旧记录未重复。原已确认游标可能领先于恢复的中心。源端已清理的历史需有可用备份。 |
| 变更中心目标 | 确认新的中心、历史起点与可见范围后再启用。按[同步恢复设计](05-同步流程与故障恢复设计.md)处理游标并核对新中心的入账情况。 |
| 升级 | 分别固定插件和 Magpie 版本。在隔离源与中心复验受影响的 API、身份、回填、权限或宿主启动后，再扩大部署。 |
| 停用或回退 | 停用来源插件，必要时撤销该来源的上报 Key。保存身份、游标和账本备份。恢复时选兼容版本与原身份，核对相同调用仍使用原 `rid`。 |
