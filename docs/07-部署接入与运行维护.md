# 部署接入与运行维护

以下步骤适用于 `0.6.0` 候选。服务器的 Docker Magpie 运行中心角色，Windows Magpie 运行来源角色。同一候选归档用于两端，安装后默认停用。切换既有部署前记录当前包、配置、网络和备份。[第七阶段验收](08-开发阶段与验收计划.md#第七阶段主动上报与明细验收)

## 中心安装与接收

1. 确认 Compose 服务及 Magpie 配置卷，在中心容器执行 `magpie --version`，并核对实际宿主 Bun 版本。将候选解包到配置卷内的版本目录，在中心容器运行 `magpie plugin add <容器内的包根目录>`。例如包的 `package.json` 位于 `/config/plugins/usage-hub/package`，就注册这个目录。[候选包核对](GitHub开源准备.md#核对公开资料与产物)
2. 在中心 Magpie Web 的 **Magpie Usage Hub** 插件页选择「中心 · 接收和查询」。填写中心本机网关 `http://127.0.0.1:3425`（按实际端口调整）、看板时区（默认 `Asia/Shanghai`）及接收端口（默认 `3494`）。同一容器内的原生网关保持回环访问。[完整字段](06-配置与诊断页面设计.md#options-与宿主校验)
3. Docker 桥接模式下，将接收监听地址设为 `0.0.0.0` 或容器内承接端口转发的网卡地址，并把容器端口**仅发布到服务器的 WireGuard 地址**。在 Compose 服务的 `ports` 增加以下条目，将 `192.0.2.2` 替换成中心实际 WireGuard 地址并应用配置，再从 Windows 测试出站。宿主网络模式直接绑定实际 WireGuard 地址。两种模式均在实际入站路径限制 WireGuard 接口及获准节点地址，单个 IPv4 对端使用 `/32`。确认公网及其他对端无法访问接收口。Magpie 页面服务 `3493` 保持回环，通过已登录的 Web 代理进入。纯 HTTP 接收限 WireGuard 或回环。使用 HTTPS 接入时保留证书校验。[端口职责](03-整体架构与模块职责.md) · [页面服务代理](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gui/pageservice.go)

   ```yaml
   ports:
     - "192.0.2.2:3494:3494/tcp"
   ```

4. 勾选「启用此实例的插件」并「保存设置」，再打开后台诊断和用量看板。确认已采用刚保存的修订并看到「中心本机」。首次扫描结束后，按同一原生周期核对本机用量。[统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计)

## Windows 上报配置

1. 在运行 Windows Magpie 的账号下解包同一归档，在 PowerShell 执行 `magpie plugin add 'C:\MagpiePlugins\usage-hub-0.6.0\package'`。路径替换成实际含 `package.json` 的目录。接通 WireGuard，运行 `Test-NetConnection -ComputerName 192.0.2.2 -Port 3494`，换成实际中心地址和端口。`TcpTestSucceeded` 应为 `True`，随后由来源插件验证上报认证。Windows 只发起出站连接，本机 Magpie 网关可以保持 `127.0.0.1:3425`。若有出站白名单，按实际策略放行中心的这一个地址和接收端口。
2. 在同一个 Windows 账号的 PowerShell 中生成令牌。以下命令新建受保护目录、写入 32 字节随机数的小写十六进制文本，再输出文件路径和 SHA-256 摘要。文件为 ASCII、无 BOM 和换行。配置使用路径，中心只登记摘要。

   ```powershell
   $usageHubKeyDirectory = Join-Path $env:LOCALAPPDATA ("MagpieUsageHub-" + [guid]::NewGuid().ToString('N'))
   New-Item -ItemType Directory -Path $usageHubKeyDirectory | Out-Null
   $usageHubSid = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
   icacls $usageHubKeyDirectory /inheritance:r /grant:r "*${usageHubSid}:(OI)(CI)F" /Q | Out-Null
   if ($LASTEXITCODE -ne 0) { throw '未能设置令牌目录权限' }

   $usageHubKeyFile = Join-Path $usageHubKeyDirectory 'report.key'
   $usageHubBytes = New-Object byte[] 32
   $usageHubRandom = [Security.Cryptography.RandomNumberGenerator]::Create()
   try { $usageHubRandom.GetBytes($usageHubBytes) } finally { $usageHubRandom.Dispose() }
   $usageHubKey = [BitConverter]::ToString($usageHubBytes).Replace('-', '').ToLowerInvariant()
   [IO.File]::WriteAllText($usageHubKeyFile, $usageHubKey, [Text.Encoding]::ASCII)
   [pscustomobject]@{
       ReportKeyFile = $usageHubKeyFile
       Digest = (Get-FileHash -LiteralPath $usageHubKeyFile -Algorithm SHA256).Hash.ToLowerInvariant()
   }
   ```

3. 在**中心**的 Magpie Web 看板打开「来源管理」，填写名称和上一步 `Digest`，保存来源。复制新条目的来源 ID。每台设备分别生成令牌并登记。
4. 回到 **Windows** 的插件页，选择「来源 · 采集和上报」，填写下表，勾选「启用此实例的插件」并保存。

   | 页面字段 | 示例或获取方式 |
   | --- | --- |
   | 来源本机网关 | `http://127.0.0.1:3425`，端口取本机 Magpie 网关实际值。 |
   | 中心接收地址 | `http://192.0.2.2:3494` 为示例，填写经 WireGuard 可达的实际中心接收根地址。 |
   | 来源 ID | 在中心创建来源后显示的 UUID。 |
   | 上报令牌文件 | 第 2 步的 `ReportKeyFile` 完整路径，文件由运行 Magpie 的 Windows 账号读取。 |

5. 保存后，从**持有本机网关的 Magpie 进程**所提供的 Web 打开「后台诊断」，启动新宿主并核对已采用修订和最近一页回执。桌面或托盘持有网关时，使用该实例「设置 → 网络与共享 → 浏览器访问」提供的本机页面。需要无窗口运行时，可由 `magpie serve --web=127.0.0.1:3430` 持有网关并提供同进程页面。核对完成后可关闭页面，保持 Magpie 和 WireGuard 运行。[查看状态与失败原因](06-配置与诊断页面设计.md) · [Magpie CLI 宿主形态](https://github.com/yetone/magpie/blob/v0.1.4799/internal/cli/web_cli.go#L222-L269)
6. 待中心显示该来源已完成同步，按相同区间和分项核对 Windows 原生用量。测试期断开后恢复 WireGuard，核对新增记录按原调用时间补进对应时间桶。`magpie serve --web` 的隔离冷启动已观察到关页后恢复上报。部署时需用实际的 Windows 登录启动方式与 WireGuard 配置验收一次。[续传和重建](05-同步流程与故障恢复设计.md) · [第七阶段验收](08-开发阶段与验收计划.md#第七阶段主动上报与明细验收)

对账时，以来源 Magpie 已采集的 `direct` 分项为准。Magpie `v0.1.4799` 读取本机会话需要用户授权，网关模式会从原生用量中排除本机直连会话。[会话读取授权](https://github.com/yetone/magpie/blob/v0.1.4799/internal/cli/sessions_cli.go#L49-L105) · [网关模式](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gui/gatewaymode.go#L95-L117)

## 日常维护

- **排查连接。** 在 Windows 先核对至中心接收口的出站 TCP，再核对本机回环网关；中心核对插件修订、监听地址、容器转发和 WireGuard 来访地址。若 TCP 通过而上报失败，根据诊断检查来源 ID、文件格式、摘要和启停状态。中心继续显示已同步的历史。[故障处理](05-同步流程与故障恢复设计.md#故障处理)
- **轮换令牌。** 在 Windows 生成新文件。在同一来源登记待验证的新摘要后，将 Windows 的「上报令牌文件」改为新路径并保存。中心确认新凭据已认证，再撤销旧凭据；原来源 ID 和检查点继续有效。
- **迁移来源。** 停止旧发送任务并备份 `push/sender.json`。本机配置目录、网关或中心地址变化时，由管理员核对源账本与目标中心。确认同一来源后，停用发送并把旧绑定文件移到备份位置，再以原来源 ID 和有效令牌重新启用。网关反馈游标身份变化时，先核对数据归属，再决定是否授权从 `start` 重建。换用另一台来源设备时在中心另行登记。
- **备份状态。** 中心数据库在 `<Magpie 配置目录>/magpie-usage-hub/push/center.sqlite`，Windows 绑定在对应的 `push/sender.json`，令牌另存。以 SQLite 一致性备份方式备份中心库，或确认停写和宿主退出后备份完整持久卷；别在写入过程中只复制主库文件。限制备份访问，记录备份时间、版本与抽样用量。
- **恢复旧备份。** 暂停上报入口和来源，停用中心并确认宿主退出，恢复同一时点的中心数据。中心打开库时在启动事务中重发来源检查点修订及管理修订，保留中心 ID、来源 ID 和各自游标。开放接收前核对恢复点后的令牌轮换及撤销记录，避免接受已撤销令牌。重新启用后让来源读取恢复后的检查点，核对缺段补传和目前原生已不可读的历史。[故障恢复](05-同步流程与故障恢复设计.md#故障处理)

## 升级与回退

1. **备份旧接入。** 备份两端固定包、Options、状态卷及防火墙规则快照，记录旧程序的端口和授权。现有 `0.5.0` 的 `pull/` 配置与 `v0.4.0` 的旧中心账本按原路径保留。`0.6.0` 通过新账本从原生可读历史回填。[`0.5.0` 部署说明](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/9daad1a8589f520256c158a6e13ea7372ca924cf/docs/07-部署接入与运行维护.md) · [`v0.4.0` 归档](https://github.com/xiao-xiao-cai/magpie-usage-hub/releases/tag/v0.4.0)
2. **完成上报切换。** 在维护窗口停用旧任务，按上文配置两端并核对首次回填、断线续传及本机模型调用。根据规则快照识别并停用 `0.5.0` 为中心 WireGuard 地址访问 Windows 网关所加的项目专用入站放行规则，恢复曾调整的入站阻止规则。确认其他业务对局域网共享的依赖后按原快照恢复共享设置。从中心检查 Windows `3425` 已关闭项目访问，检查 Windows 原生回环和至中心 `3494` 的上报仍可用。回退窗口结束后撤销旧专用只读 Key。
3. **回退。** 停用新版两端任务并确认退出，保全 `push/` 状态及来源令牌。按原快照恢复旧包、Options、状态和授权。若回退到 `0.5.0`，恢复当时登记的专用只读 Key 和 Windows 精确入站规则，再核对中心与 Windows 各自的原生汇总。再次切换至 `0.6.0` 时沿用其中心账本与来源绑定继续。[`0.5.0` 回退](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/9daad1a8589f520256c158a6e13ea7372ca924cf/docs/07-部署接入与运行维护.md#升级与回退) · [`v0.4.0` 试用接入与回退](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/v0.4.0/docs/07-部署接入与运行维护.md#第五阶段试用接入)
