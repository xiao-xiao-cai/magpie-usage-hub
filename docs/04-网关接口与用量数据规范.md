# 网关接口与用量数据规范

中心接收 Windows Magpie 的原生 OTLP Trace，并从中心本机的回环网关读取原生用量变更。已登录的浏览器经 Magpie Web 页面服务代理查询中心明细和管理来源。下文路径相对于各自的服务根地址。

## 原生网关查询

| 用途 | 请求 | 约定 |
| --- | --- | --- |
| 中心本机采集 | `GET /v1/magpie/usage/requests?cursor=start&limit=100` | 首次从 `start` 读取可见历史，之后从 SQLite 已提交的游标继续。读取完整变更流的 `rows`、`deleted`、`next_cursor` 与 `has_more`。原生响应超过 1 MiB 时，从同一游标缩小 `limit` 重试。 |
| 中心本机对账 | `GET /v1/magpie/usage/requests?computer=this&period=7d&offset=0&limit=1` | `period` 可取 `today`、`7d` 或 `30d`。核对原生时间起点和 `through`、`direct` 分项。 |

中心本机读取完整变更流以应用删除及记录移出范围时的撤销。原生 `computer` 缺省或为空时，`origin=gateway` 的行写为 `through`，`origin=session` 的行写为 `direct`。原生 `id` 转为 SHA-256 行键，`seq` 决定行更新和撤销的先后顺序。[原生游标接口](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gateway/usage_api.go#L74-L123) · [原生变更页字段](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usageapi/feed.go#L10-L68)

## 中心接收接口

中心在独立监听地址接收 `POST /v1/traces`，请求路径不带查询参数，默认绑定 `127.0.0.1:3494`。发送未压缩的 UTF-8 `application/json`，使用 `Authorization: Bearer <来源令牌>`。令牌为 64 个小写 ASCII 十六进制字符，中心对这 64 个字符计算 SHA-256，与已登记摘要比对并据此归属来源。每个摘要只能登记在一个凭据槽。Linux 原生中心直接监听服务器的 WireGuard 地址，Docker 桥接中心发布到该地址。[中心安装与接收](07-部署接入与运行维护.md#中心安装与接收)

请求体采用 `resourceSpans[].scopeSpans[].spans[]`。接收端先校验外层数组和批次限额，再处理 `scope.name` 为 `github.com/yetone/magpie`、带用量属性的 `generation`。网关尝试为 `kind=3`、有有效的 `parentSpanId` 且没有会话标记，映射为 `via=through`。带非空会话标记的原生会话生成是 `kind=1`，映射为 `via=session`。其他 scope、网关根 span、会话根和工具 span 不计为用量。[Magpie Trace 格式](https://github.com/yetone/magpie/blob/v0.1.4799/internal/otlp/otel_wire.go#L64-L68) · [Span 与分项](https://github.com/yetone/magpie/blob/v0.1.4799/internal/otlp/otel_wire.go#L131-L211)

| 接收字段 | 类型、单位与落库规则 |
| --- | --- |
| `traceId`、`spanId` | 分别为 32 位和 16 位非全零十六进制文本。转换成小写，以 `traceId:spanId` 的 ASCII SHA-256 为行键。同一来源和行键保留第一次接收的快照。 |
| `startTimeUnixNano`、`endTimeUnixNano` | 十进制字符串，单位 Unix 纳秒，从 1 到 `9223372036854775807`。结束不得早于开始。明细 `t` 保存开始时间的 9 位小数 UTC 表示，筛选和分桶使用毫秒。`durationMs` 为时间差取整到毫秒。 |
| `gen_ai.request.model` | `stringValue`，最长 512 个 UTF-16 代码单元，排除 C0 控制字符和 DEL。空字符串在界面显示「未标注模型」。 |
| `gen_ai.usage.input_tokens`、`gen_ai.usage.output_tokens` | `intValue` 为非负安全整数的十进制字符串。输入计数含缓存，明细 `input` 扣除缓存读写以单列汇总；`output` 保留原输出总量。 |
| `gen_ai.usage.cache_read.input_tokens`、`gen_ai.usage.cache_creation.input_tokens`、`gen_ai.usage.reasoning.output_tokens` | 与输入和输出使用同一数值格式。已选中的 span 须提供五项 Token 数，缓存读写之和不得超过输入总数。推理 Token 已包含在输出总数内。 |
| `langfuse.observation.cost_details` | 可选 `stringValue`，为含数值 `total` 的 JSON 字符串。`total` 是 Magpie 估算费用，单位 USD，范围为 0 至 `Number.MAX_SAFE_INTEGER`。属性缺失时写 `null`。 |
| `http.response.status_code` | 网关尝试使用十进制字符串 `intValue`，范围 100–599。缺失、值为 0 或会话生成时，明细 `status` 为 `null`。 |

每个请求体最多 4 MiB，资源组和作用域组总计最多 128 个，span 总计最多 128 条，逐 span 最多 128 个属性（对候选 `kind=1` 或 `kind=3` 解析）。同时处理的请求最多 16 个，同一来源最多 2 个。成功应答在 SQLite 事务提交后发出。

| 情况 | HTTP 响应 |
| --- | --- |
| 完整接受，或批次只有无需采集的 span | `200 {}`。只有带有效用量的批次更新「最近接收」。 |
| 有有效用量，另有受理范围内的无效 span | 提交有效用量，返回 `200 {"partialSuccess":{"rejectedSpans":"1"}}`，计数为十进制字符串。 |
| JSON 或外层结构无效、资源组或 span 数超限，或存在无效 span 且没有有效用量 | `400 invalid_otlp_traces`，整批不写入。 |
| 令牌格式错误或摘要未登记 | `401 report_key_invalid`。 |
| 来源已暂停或凭据对应只读历史来源 | `403 source_paused` 或 `403 source_transport_inactive`。 |
| 路径或方法错误 | `404 ingest_route_not_found` 或 `405`，后者带 `Allow: POST`。 |
| 请求体超限或格式不支持 | 请求体超限为 `413`（应用层代码 `otlp_body_too_large`），不支持的媒体类型或压缩编码为 `415 unsupported_media_type`。 |
| 并发超限或存储失败 | `429 ingest_rate_limited` 或 `503 ingest_unavailable`，存储失败时回滚本批。 |

## 怎样解释中心统计

看板按原调用时间筛选和分桶，使用中心配置的时区计算预设周期与日界，小时桶保留实际偏移。中心本机对账使用原生周期的起点和同一采样截止时间，逐项比较 `through` 和 `direct`。看板默认统计网关分项。「会话」合计 `direct` 与 `session`。在「全部分项」中，同一次业务调用可能同时计入网关和会话。主 Token 指标为非缓存输入加输出，缓存单列，推理已含在输出中。覆盖区间是该来源已发布明细的最早与最晚时间。[原生日界与分桶](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usage/ledger.go#L884-L977)

| 看板 `totals` 字段 | 语义 |
| --- | --- |
| `calls` | OTLP 每条用量观测计一次。中心本机和历史来源按原生请求计数，`handedOn=false` 的行各计一次；中间尝试的 Token 与符合计价条件的费用仍并入。 |
| `input`、`output`、`cacheRead`、`cacheWrite`、`reasoning` | 非缓存输入、输出、缓存读、缓存写与推理 Token 总量。 |
| `cost` | Magpie 估算费用之和，单位 USD。OTLP 汇总收到的所有有效估价，含纯缓存用量。中心本机与历史来源汇总 `input + output > 0` 的已计价行。 |
| `unpriced` | 有 Token 用量且缺少估价的记录数。OTLP 同时检查输入、输出和缓存读写计数。中心本机与历史来源检查 `input + output > 0`。 |
| `cacheUnknownCalls` | 缓存用量未知的明细行数，适用于原生游标记录。 |

空区间指标为零。`cost: 0` 和 `unpriced: 2` 表示已计价估算费用共 USD 0，另有 2 条缺价记录。OTLP 估价取首次接收的快照，中心本机估价可随原生明细修订或重建更新。实际账单以供应商计量为准。[原生费用和请求数](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usage/usage.go#L1009-L1073) · [Trace 计价字段](https://github.com/yetone/magpie/blob/v0.1.4799/internal/otlp/otel_wire.go#L192-L210)

## 看板与管理接口

通过已登录的 Magpie Web 页面代理，`GET /api/usage` 与 `GET /api/usage/rows` 使用 `X-Magpie-Usage-Query`。两者均可指定 `sourceId`、`model`、`via=through|direct|session|conversation`，并选择 `period=today|7d|30d` 或同时指定 `from` 与 `to`。`conversation` 匹配 `direct` 和 `session`，省略 `via` 查询全部分项。自定义范围为带偏移的 RFC3339 时间 `[from,to)`，查询精确到毫秒。默认查询近 7 天，含当前日。查询某一小时可传 `from=2026-11-27T01:00:00Z&to=2026-11-27T02:00:00Z`。URL 中的正偏移符号 `+` 编码为 `%2B`。

| 请求 | 返回及附加参数 |
| --- | --- |
| `GET /api/usage` | 返回 `{ range, sources }`。来源项包含 `transport`（`local`、`legacy` 或 `otlp`）、状态、覆盖区间、`totals`、`models` 及 `buckets`。`gap` 描述本机重建发现的缺口。可指定 `bucket=hour` 查最多 31 日或 `bucket=day` 查最多 366 日的趋势。 |
| `GET /api/usage/rows` | 返回 `{ range, rows, nextPage }`。明细按原调用时间倒序，单页默认 50 行、最多 100 行。下一页携带 `page`，沿用来源、模型与分项筛选。如果首屏使用相对周期或默认时段，翻页时用首屏返回的 `range.from`、`range.to` 固定窗口。服务重启、活动数据集切换或筛选变化时，从第一页重新查询。 |

管理请求使用 `X-Magpie-Usage-Admin`。`GET /api/sources` 返回 `{ revision, sources }`，包括来源 ID、名称、启停、`transport`、阶段和凭据槽状态。`POST /api/sources` 携带 `revision` 与 `action`，成功返回新修订和脱敏列表。

| `action` | 附加字段 |
| --- | --- |
| `create` | `name`、`digest`（令牌的 SHA-256 摘要）、可选 `enabled`（默认 `true`）。成功返回 `201`。可传小写 UUIDv4 `id`，用于创建响应丢失后精确查找来源。省略时由中心生成。已存在的 ID 返回 `409 source_id_in_use`。 |
| `update` | OTLP 来源 `id` 及至少一项 `name` 或 `enabled`。 |
| `rotate` | OTLP 来源 `id`、新的 `digest`。 |
| `revoke` | OTLP 来源 `id`、`slot`，取 `current`、`pending` 或 `all`。 |
| `rebuild` | `id=local`，适用于等待确认重建的中心本机。 |

查询或管理令牌不符返回 `403`，旧管理修订返回 `409 source_revision_conflict`。浏览器明细返回来源、时间、分项、模型、用量、计价和请求状态。中心只持久化白名单用量字段和行键，OTLP 会话标记仅用于选择分项，来源令牌原文与模型请求及响应正文不落入账本。[页面操作](06-配置与诊断页面设计.md)
