# 网关接口与用量数据规范

来源和中心本机从各自的回环网关读取原生变化。独立接收服务接受来源上报，浏览器经 Magpie Web 页面服务代理查询中心明细和管理来源。下文路径相对于各自的服务根地址。

## 原生网关查询

| 用途 | 请求 | 约定 |
| --- | --- | --- |
| 记录采集 | `GET /v1/magpie/usage/requests?cursor=start&limit=100` | 首次从 `start` 读取可见历史，之后按中心确认的原生游标继续。读取完整变更流的 `rows`、`deleted`、`next_cursor` 与 `has_more`，原生响应超限时从同一游标缩小 `limit` 重试。 |
| 原生对账 | `GET /v1/magpie/usage/requests?computer=this&period=7d&offset=0&limit=1` | `period` 可取 `today`、`7d` 或 `30d`。核对原生时间起点及同页 `through`、`direct` 分项。 |

原生 `computer` 缺省或为空，且 `origin` 为 `gateway` 或 `session` 的记录分别写为 `through` 和 `direct`。源端仍读取完整变化流，以应用原生删除及记录移出采集范围时的撤销。原生 `id` 转为不透明的 SHA-256 `rowKey`，删除和排除只发送 `rowKey` 与 `seq`。[原生游标接口](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gateway/usage_api.go#L74-L123) · [原生变更页字段](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usageapi/feed.go#L10-L68)

## 中心接收接口

接收请求使用 `Authorization: Bearer <来源令牌>`，由摘要识别唯一来源。中心绑定 `3494` 或配置的接收端口，与回环页面服务分开。HTTP 用于 WireGuard 或回环，HTTPS 校验证书，来源拒绝重定向。[部署入口](07-部署接入与运行维护.md#中心安装与接收)

| 请求 | 请求体和成功响应 |
| --- | --- |
| `GET /v1/usage-hub/checkpoint` | 返回 `centerId`、`sourceId`、当前 `revision`、`cursor`、`phase`、`hasMore` 和 `lastSyncedAt`。首次回填与重建从 `start` 开始。 |
| `POST /v1/usage-hub/pages` | JSON `{ sourceId, revision, nextCursor, hasMore, upserts, removals }`。成功返回 `{ checkpoint, upserted, removed }`，其中 `checkpoint` 是持久化后的进度。 |
| `POST /v1/usage-hub/recovery` | JSON `{ sourceId, revision, reason }`，用于上报原生游标故障。成功返回更新后的检查点。 |

一页总变更数最多 100，页面提交体最多 1 MiB，恢复报告最多 4 KiB。`upserts` 每项含 `rowKey`、原生流版本 `seq`、带偏移的原调用时间 `t`、`via`、`model`、`handedOn`、`input`、`output`、`cacheRead`、`cacheWrite`、`reasoning`、`cacheUnknown`、`cost`、`status`、`durationMs`。Token 和时长采用非负整数，时长单位为毫秒。费用缺价、状态或耗时不可用以 `null` 表示。`removals` 每项含 `rowKey` 与 `seq`。

凭据失效返回 `401 report_key_invalid`，跨来源写入或暂停来源写入返回 `403`，预期修订已过期返回 `409 checkpoint_conflict`，并发超限返回 `429 ingest_rate_limited`。用 `error.code` 处理受控错误。重试、失效和重建路径见[同步与故障恢复](05-同步流程与故障恢复设计.md)。

## 怎样解释中心统计

看板按原调用时间筛选和分桶，使用中心配置的时区计算预设周期与日界，小时桶保留实际偏移。和原生网关对账时，使用该来源的原生周期起点和同一采样截止时间，比较本机 `through` 与 `direct` 分项。一条经由另一实例转发的业务请求可以在两个原生账本各有计量记录，汇总按各自来源解释。[原生日界与分桶](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usage/ledger.go#L884-L977)

| 看板 `totals` 字段 | 语义 |
| --- | --- |
| `calls` | `handedOn` 为 `false` 的行各计一次请求。中间尝试的 Token 和符合计价条件的费用仍纳入汇总。 |
| `input`、`output`、`cacheRead`、`cacheWrite`、`reasoning` | 输入、输出、缓存读和写及推理 Token 总量。 |
| `cost` | 输入加输出大于零的已计价行的原生估算费用之和，单位 USD。 |
| `unpriced` | 输入加输出大于零且原生价格缺失的记录数。 |
| `cacheUnknownCalls` | 原生缓存用量为未知的明细行数。 |

空区间指标为零。`cost: 0`、`unpriced: 2` 表示已计价估算费用共 USD 0，另有 2 条缺价记录。源端的历史估价可随明细修订或重建更新。实际账单以供应商计量为准。[原生费用和请求数](https://github.com/yetone/magpie/blob/v0.1.4799/internal/usage/usage.go#L1009-L1073)

## 看板与管理接口

`GET /api/usage` 与 `GET /api/usage/rows` 使用 `X-Magpie-Usage-Query`。两者均可指定 `sourceId`、`model`、`via=through|direct`，并选择 `period=today|7d|30d` 或同时指定 `from` 与 `to`。自定义范围为带偏移的 RFC3339 时间 `[from,to)`，查询精确到毫秒。默认查询近 7 天，含当前日。示例查询过去一个小时可传 `from=2026-11-27T01:00:00Z&to=2026-11-27T02:00:00Z`。若参数含正偏移，在 URL 中将 `+` 编码为 `%2B`。

| 请求 | 返回及附加参数 |
| --- | --- |
| `GET /api/usage` | 返回 `{ range, sources }`。来源项包含同步阶段、覆盖区间、缺口、`totals`、`models` 及 `buckets`。可指定 `bucket=hour` 查最多 31 日或 `bucket=day` 查最多 366 日的趋势。 |
| `GET /api/usage/rows` | 返回 `{ range, rows, nextPage }`。明细按原调用时间倒序，单页默认 50 行、最多 100 行。下一页携带 `page`，沿用来源、模型与分项筛选。如果首屏使用相对周期或默认时段，翻页时用首屏返回的 `range.from`、`range.to` 固定窗口。服务重启、活动数据集切换或筛选变化时，从第一页重新查询。 |

管理请求使用 `X-Magpie-Usage-Admin`。`GET /api/sources` 返回 `{ revision, sources }`，包括来源 ID、名称、启停、同步状态和凭据槽状态。`POST /api/sources` 携带 `revision` 与 `action`，成功返回新修订和脱敏列表。

| `action` | 附加字段 |
| --- | --- |
| `create` | `name`、`digest`、可选 `enabled`，成功返回 `201` 并生成来源 ID。 |
| `update` | `id` 及至少一项 `name` 或 `enabled`。 |
| `rotate` | `id`、新的 `digest`。 |
| `revoke` | `id`、`slot`，取 `current`、`pending` 或 `all`。 |
| `rebuild` | `id`，适用于等待恢复的同一来源。 |

查询或管理令牌不符返回 `403`，旧管理修订返回 `409 source_revision_conflict`。原生请求标识、Account 和会话标识、机密、正文及原始错误保留在各自的受控边界。浏览器明细字段只包括来源、时间、模型、用量和状态。[页面操作](06-配置与诊断页面设计.md)
