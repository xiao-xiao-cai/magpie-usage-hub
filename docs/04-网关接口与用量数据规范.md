# 网关接口与用量数据规范

中心 Bun 使用原生网关的只读 HTTP 接口。浏览器经 Magpie 页面服务代理读取脱敏汇总。下文路径相对于各自服务的根地址。

## 原生网关查询

| 执行时机 | 请求 | 校验与用途 |
| --- | --- | --- |
| 看板打开、切换周期或刷新 | `GET /v1/magpie/usage/requests?computer=this&period=7d&offset=0&limit=1` | `period` 取 `today`、`7d` 或 `30d`。核对响应周期，读取同页本机 `through` 与 `direct` 的统计，`rows` 留在服务端。 |
| 管理员测试远程来源 | 同一个汇总 GET，加 `GET /v1/magpie/usage?period=today` | 两个请求共用一次超时预算。第二个请求识别 `gateway_key_held`，用于发现用量可见范围受限的 Key。Key 的只读资格由签发设置保证。 |

中心本机走容器内回环。同宿主回环请求按 Magpie 的本机鉴权处理。远程来源使用已登记的 HTTP(S) 根地址与 `Authorization: Bearer <专用只读 Key>`。客户端直连，校验证书，限制响应大小，拒绝重定向。每一轮查询最多同时处理 4 个来源。[请求页处理](https://github.com/yetone/magpie/blob/v0.1.4874/internal/gateway/usage_api.go#L50-L94) · [同页汇总与时间桶](https://github.com/yetone/magpie/blob/v0.1.4874/internal/usageapi/usageapi.go#L274-L324) · [受限 Key 分类](https://github.com/yetone/magpie/blob/v0.1.4874/internal/provider/remote_quotas.go#L121)

## 怎样解释中心统计

看板按实例、按原生周期对账。`computer=this` 选择该实例的本机记录，汇总由 `through` 和 `direct` 逐指标相加。`reported` 是独立分项。若原生响应提供 `series[0].time`，看板展示该起点并保留时区偏移。即使两个来源选择同一周期，原生日期边界也可能不同。[本机筛选](https://github.com/yetone/magpie/blob/v0.1.4874/internal/usage/ledger.go#L169-L183) · [原生起点与分桶](https://github.com/yetone/magpie/blob/v0.1.4874/internal/usage/ledger.go#L884-L977)

| 原生分项字段 | 看板 `totals` 字段 | 语义 |
| --- | --- | --- |
| `calls` | `calls` | 按原生请求口径统计的非负整数。 |
| `input`、`output` | `input`、`output` | 输入与输出 Token，非负整数。 |
| `cache_read`、`cache_write` | `cacheRead`、`cacheWrite` | 缓存读取与写入的 Token，非负整数。 |
| `cost` | `cost` | 已计价估算费用，有限非负数，单位 USD。 |
| `unpriced` | `unpriced` | 原生缺价记录数，非负整数。 |

空周期的已知指标显示为零。例如返回 `cost: 0`、`unpriced: 2` 时，已计价估算费用为 `USD 0`，另有 2 条缺价记录。实际账单以供应商计量为准。`0.5.0` 使用原生 `calls`。回看旧版看板数据时，`0.4.0` 的明细行计数对应计量尝试。[原生请求数与费用口径](https://github.com/yetone/magpie/blob/v0.1.4874/internal/usage/usage.go#L619-L650) · [旧版看板口径](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/v0.4.0/docs/04-网关接口与用量数据规范.md#怎样解释中心统计)

## 看板与管理接口

`GET /api/usage?period=7d` 返回 `usage-v2` 查询结果。每个来源返回名称、`status`、`since`、`checkedAt`、`totals` 和 `failure`。`status` 取 `ok`、`unavailable` 或 `paused`，`since` 与 `checkedAt` 可以为 `null`。失败以 `failure.code` 和可选 `failure.httpStatus` 表达。类别包括 `unauthorized`、`forbidden`、`timeout`、`unavailable`、`incompatible_response`、`redirect` 和 `restricted_key`。看板按类别显示受控提示。[页面状态](06-配置与诊断页面设计.md#中心-web-用量看板)

管理请求经同一 Web 入口提交，携带 `X-Magpie-Usage-Admin`。

| 请求 | 请求和响应 |
| --- | --- |
| `GET /api/sources` | 返回 `revision` 和 `sources`。每项包含稳定的 `id`、`name`、`gatewayUrl`、`enabled` 与 `credentialConfigured`。 |
| `POST /api/sources` | 提交 `{id?, revision, name, gatewayUrl, enabled, key?}`。新增时省略 `id`，新增或更改地址时填 `key`。成功返回新修订和脱敏列表。 |
| `POST /api/sources/test` | 使用与保存相同的草稿形状，返回 `status`（`ok` 或 `unavailable`）、`checkedAt` 与 `failure`。 |

令牌不符返回 `403`。无效配置或缺必填 Key 返回 `400 invalid_source` 或 `400 key_required`。未知 ID 返回 `404 source_not_found`。旧修订返回 `409 revision_conflict`。持久化失败返回 `503 source_save_failed`，上次已提交配置保持可用。[编辑和重试](06-配置与诊断页面设计.md#来源管理)
