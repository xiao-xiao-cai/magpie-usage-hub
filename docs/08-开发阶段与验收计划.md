# 开发阶段与验收计划

当前阶段为 `0.7.0` 候选的原生 OTLP 接入。每次改动选择能证明预期行为及失败条件的检查。[原生 OTLP 接入验收](#原生-otlp-接入验收)

## 里程碑

| 阶段 | 交付内容 | 进入下一阶段的依据 |
| --- | --- | --- |
| 1. 跑通用量链路 | 在两个独立的 Magpie 实例间打通源端游标读取、字段映射、中心 POST 与只读查询。 | 一条测试用量进入中心 `reported`，一条直接调用归为 `through`。分别核对字段、凭据与查询结果。 |
| 2. 持久进度和恢复 | 实现来源身份、锁、整页确认、原子状态写入、重放及退避。 | 在中断位置读回持久游标，验证恢复后每个预期 `rid` 恰好一条，源端模型路径在中心离线时可用。 |
| 3. 配置与诊断 | 接入 Options、Web 服务页和桌面配置桥，提供受控恢复入口。 | 每种声明支持的形态都有独立记录，能判断配置是否已保存、调度是否已生效、故障如何恢复。 |
| 4. 多来源与计量 | 两个独立来源并发向同一中心上报专用测试 Key 的计量行。验证独立撤销、原游标补传和只读权限。 | 两个来源可独立追查。撤销 A 时 B 仍能入账，A 恢复后沿用身份补传，回填同一条在中心仍恰有一条。 |
| 5. 托管试用与独立看板 | 同包部署到 Windows 来源和 Docker 中心。中心配置具名来源，节点配对后从 `now` 采集专用 Key 与供应商的匹配用量。 | 一次配对后中心能调整启停与间隔。看板对账、入口鉴权、暂停续传、断链重放和关页冷启动通过。旧原生上报的清理单独确认维护窗口与原游标续读。 |
| 6. 中心只读拉取 | 只在中心 Docker Magpie 安装插件，从容器内回环及受限的 WireGuard 路径读各实例的原生汇总。 | Web 可管理来源并轮换 Key。按来源、周期与原生汇总对账。单来源失联、恢复、宿主重载和固定版本回退均有记录。 |
| 7. 主动上报与明细 | 两端运行同一候选，来源读取回环原生变化并上报，中心保存明细与检查点。 | Windows 通过出站完成回填、断线续传和轮换。中心按调用时间筛选、分桶及查询明细；实机对账、访问边界和回退均有记录。 |
| 8. 原生 OTLP 接入 | Windows 原生 Magpie 经 WireGuard 发送 trace，中心插件接收并保存用量明细。 | 上游导出、来源认证、重试去重、时段筛选和宿主重启后读回通过。实机网络边界和升级回退按维护窗口确认。 |

## 按改动选择验证级别

| 级别 | 本项目的最小验证示例 | 何时停止 |
| --- | --- | --- |
| L0 静态检查 | 改 README 或字段说明时核对引用、本地链接和与目标版本的一致性。改 Skill 时另验元数据、引用和路由。 | 本次陈述或入口均有对应依据。 |
| L1 定向验证 | 用合成分项验证统计口径、零值和异常值。按钮样式检查受影响主题、普通态及键盘焦点。 | 确认被改的输出和边界值。 |
| L2 模块集成 | 用回环模拟网关验证查询与失败处理。用临时目录验证写入和读回，页面读写用可控响应覆盖竞态。 | 输出、持久状态和故障后的恢复结果均符合约定。 |
| L3 宿主验收 | 宿主重载或页面桥用一套实际 Magpie，跨网关链路用来源和中心。使用现有节点时按验收授权范围操作。 | 在目标版本及所声明的形态观察到相关行为和失败条件。 |

各级可直接选择。发现共享调用方受影响，增加该调用方的检查。模拟与宿主表现不一致，升级到相应形态的 L3。全量回归适用于明确要求、发布验收约定或影响分析仍无法划定范围的基础改动。下表按涉及的场景选用。详见[项目分级测试规范](../.agents/skills/magpie-testing/SKILL.md)。
