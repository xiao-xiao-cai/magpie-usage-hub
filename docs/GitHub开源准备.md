# GitHub 首次开源准备

本页用于核对公开的候选版本、文件范围、许可状态和 Magpie 安装入口。

## 确定公开范围

- 确认目标 GitHub 仓库、可见性、候选提交、分支、标签与随附文件。源码、项目文档、开发 Skills、仓库配置、锁文件和已审核的合成示例可纳入候选。
- 审查候选提交及拟公开分支、标签可达的历史，包括作者邮箱、附件和历史删除的内容。排查凭据、真实用量、同步状态、会话内容、个人路径和私有服务地址。发现敏感内容先暂停公开，按维护者确认的范围处理。涉及泄露凭据时检查是否需要吊销与轮换。
- 核对第三方代码、文档及资产的公开条件。发布项目许可证时，由维护者选定许可证和版权主体，并补齐适用的归属声明。

## 核对公开资料与产物

- README 应反映候选版本的实际状态、可用功能和验证范围。随首发提供插件包时，补齐安装、权限、配置、升级、停用等用户需要的信息。
- 如果首发包含可分发插件，核对版本、提交、标签和打包范围。npm 候选可用 `npm pack --dry-run --ignore-scripts --json` 检查清单，并用实际产物在隔离 Magpie 试装。通过 Git 分发时，用将公开的固定提交试装。

## 发布后的应用内安装

- 通过 GitHub 发布时，把 `package.json`、后台入口和页面资源放在公开仓库的根目录结构中。用户可在 Magpie「插件 → 发现 → 已有想装的？」填入 `github:xiao-xiao-cai/magpie-usage-hub#main` 安装主分支。按标签发布时，使用相应的标签替换 `main`。[Magpie 插件安装](https://usemagpie.ai/docs/zh/plugins#run)

## 公开和确认结果

- 本地整理完成后，由维护者确认本次要执行的远端操作及范围。推送、设置公开可见性、创建 GitHub Release、上传资产和发布包分别以获准范围为准。
- 完成获准操作后，核对远端可见性、实际提交与文件，按需核对 Release、下载产物或包版本。记录可访问的入口和待完成项。
