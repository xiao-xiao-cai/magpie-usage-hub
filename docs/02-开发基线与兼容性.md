# 开发基线与兼容性

`0.5.0` 候选以 Magpie `v0.1.4874` 为源码核对基线。部署时记录中心 Docker、Windows 来源和中心宿主 Bun 的实际版本。[Magpie `v0.1.4874`](https://github.com/yetone/magpie/releases/tag/v0.1.4874) · [第六阶段验收](08-开发阶段与验收计划.md#第六阶段中心只读拉取验收)

## 实现应依赖的接口

| 接入点 | 兼容性约定 |
| --- | --- |
| Bun 入口 | 包的 `exports["./server"]` 指向 `server.ts`，默认导出 `{ id, server }`。入口接收 `server(input, options)`，中心进程核对回环网关与宿主归属后竞争运行锁。 |
| 配置与路径 | `options` 来自插件安装项。`input.directory` 用于定位专用状态目录，`import.meta.url` 用于找包内页面。原生网关使用已验证的显式地址。 |
| Options 与页面服务 | `magpie.page.file` 提供普通配置页，经 `magpie.ready` 后使用 Options。Web 通过 `magpie.service` 导航到宿主指定的回环服务，桌面配置页在服务入口为空时提示使用 Web。 |
| 原生网关 | 查询需要 `GET /v1/magpie/usage/requests` 支持所选周期、`computer=this` 及同页 `through`、`direct` 汇总。远程网关需要允许中心出站来源和未受范围限制的专用只读 Key。 |

[Magpie 插件文档](https://usemagpie.ai/docs/plugins) · [页面服务源码](https://github.com/yetone/magpie/blob/v0.1.4874/internal/gui/pageservice.go#L18-L34) · [原生请求汇总](https://github.com/yetone/magpie/blob/v0.1.4874/internal/usageapi/usageapi.go#L275-L303) · [来源地址限制](https://github.com/yetone/magpie/blob/v0.1.4874/docs/reference.md#L1009-L1020)

## 升级时怎样复核

1. 在各实例执行 `magpie --version`，核对中心实际运行插件的 Bun 版本和候选归档。以相应版本标签解释版本差异。[Magpie 发行记录](https://github.com/yetone/magpie/releases)
2. 从中心容器内分别访问原生回环网关和来源的 WireGuard 网关。核对真实来访地址、只读鉴权及原生响应结构。[部署接入](07-部署接入与运行维护.md)
3. 在实际 Web 验证登录、Options 保存和读回、页面服务代理、管理令牌及宿主重载。临时 `magpie plugin list --json` 可能加载其自己的 Bun，只能证明该 CLI 进程的加载结果。[配置与诊断](06-配置与诊断页面设计.md)
