# 开发基线与兼容性

`0.6.0` 候选以 Magpie `v0.1.4799` 的原生变更接口和页面服务为核对基线。部署时记录中心 Docker、Windows 来源以及两端 Bun 的实际版本。[Magpie `v0.1.4799`](https://github.com/yetone/magpie/releases/tag/v0.1.4799) · [第七阶段验收](08-开发阶段与验收计划.md#第七阶段主动上报与明细验收)

## 实现应依赖的接口

| 接入点 | 兼容性约定 |
| --- | --- |
| Bun 入口 | `exports["./server"]` 指向 `server.ts`，默认导出 `{ id, server }`。`server(input, options)` 在宿主返回后异步启动所选角色；运行任务在回环网关核对 Magpie PID 后取得插件状态锁。中心依赖 Bun 的 SQLite 支持。 |
| 配置与路径 | `options` 来自插件安装项。`input.directory` 用于定位专用状态目录，`import.meta.url` 定位包内页面。两端的原生采集网关均配置回环根地址。 |
| Options 与页面服务 | `magpie.page.file` 提供配置页，经 `magpie.ready` 使用 Options。Web 通过 `magpie.service` 导航到 `3493` 回环页面服务。桌面配置页在服务入口为空时提示使用本机 Web 诊断。 |
| 原生网关 | `GET /v1/magpie/usage/requests` 提供 `cursor=start` 及续读、`rows`、`deleted`、`next_cursor` 和 `has_more`。用 `computer=this` 的 `through` 与 `direct` 汇总核对计量。 |

[Magpie 插件文档](https://usemagpie.ai/docs/plugins) · [页面服务源码](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gui/pageservice.go) · [原生游标接口](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gateway/usage_api.go#L74-L123)

## 升级时怎样复核

1. 在各实例执行 `magpie --version`，核对实际宿主 Bun 版本和两端安装的候选归档。以对应版本标签解释差异。[Magpie 发行记录](https://github.com/yetone/magpie/releases)
2. 在各自宿主内核对原生回环的游标起读、续读和响应字段，再从 Windows 核对至中心 WireGuard 接收口的连通性和认证上报。[部署接入](07-部署接入与运行维护.md)
3. 在实际 Web 验证登录、Options 保存读回、代理访问、管理与查询权限以及宿主交接。临时 `magpie plugin list --json` 的加载结果仅覆盖该 CLI 进程。[配置与诊断](06-配置与诊断页面设计.md)

旧版按固定提交或标签追溯。`0.5.0` 的原生汇总源码基线为 `v0.1.4874`。`0.4.0` 曾在 Windows Magpie `v0.1.4799` 和 Bun `1.4.5` 验证隔离安装与合成上报。[第六阶段验收](08-开发阶段与验收计划.md#第六阶段中心只读拉取验收) · [`v0.4.0` 开发基线](https://github.com/xiao-xiao-cai/magpie-usage-hub/blob/v0.4.0/docs/02-开发基线与兼容性.md)
