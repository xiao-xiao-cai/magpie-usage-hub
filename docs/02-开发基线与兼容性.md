# 开发基线与兼容性

首版以 Magpie `v0.1.4783` 为接口核对基线。开发时记录实际 Magpie 版本、宿主 Bun 版本、运行形态和插件版本。公开接口决定插件如何接入，对应标签源码用于解释字段、限制与宿主行为。[版本发行记录](https://github.com/yetone/magpie/releases) · [原生网关参考](https://github.com/yetone/magpie/blob/v0.1.4783/docs/reference.md)

第一阶段实测组合为 Windows Magpie `v0.1.4795` 来源端和 Docker Magpie `v0.1.4572` 中心。来源端的游标请求使用 `callerKey` 筛选单次验证用量。宿主加载、中心入账及权限的观察结果见验收记录。[v0.1.4795 用量筛选源码](https://github.com/yetone/magpie/blob/v0.1.4795/internal/usageapi/usageapi.go) · [开发阶段与验收计划](08-开发阶段与验收计划.md)

## 实现应依赖的接口

| 接入点 | 基线约定 | 实现时怎样使用 |
| --- | --- | --- |
| 后台入口 | Magpie 管理 Bun，基线内置选择为 `1.4.2`。项目使用严格模式 TypeScript、ESM，包的 `exports["./server"]` 指向服务端入口（如 `./server.ts`）。 | 默认导出带 `id` 和 `server(input, options)` 的对象。校验 Options，取得任务所有权后启动后台循环，尽快返回以便宿主继续加载。 |
| 配置与路径 | `options` 来自插件安装项。`input.directory` 指向 Magpie 配置目录，`input.serverUrl` 是兼容入口的占位值。 | 用显式配置的源与中心 URL 访问网关。在配置目录下建立插件专用子目录。用 `import.meta.url` 定位只读的包内资源。 |
| 插件页面 | `magpie.page.file` 注册原生 HTML、CSS、JavaScript 页面，使用官方页面桥。Web 可声明 `magpie.page.service`。 | 等待 `magpie.ready` 后使用 Options 或读取服务入口。桌面桥的 `magpie.service` 为空，具体呈现见[配置与诊断页面设计](06-配置与诊断页面设计.md)。 |
| 用量采集 | 原生请求游标支持按确认位置续读。`onUsage` 是异步钩子，单次预算 250 ms，队列满时可丢事件。 | 可靠采集使用公开的网关游标和源行 ID。把读页和上报放在 Bun 的独立任务中。 |
| 用量接收与查询 | 中心原生上报路由接收用量，另有汇总与明细读取接口。 | 按[网关接口与用量数据规范](04-网关接口与用量数据规范.md)构造请求，分别配置上报和只读凭据。 |

## 不同运行形态的证据

| 形态 | 已有依据 | 声明支持所需的隔离验证 |
| --- | --- | --- |
| 本机网关 | 既有只读记录覆盖 `v0.1.4758` 的汇总、明细和起始及续读游标。`v0.1.4783` 已核对汇总与游标入口。 | 用目标版本的源和中心验证真实写入、逐项回执、重放与两种来源分类。 |
| 临时 CLI | Windows 隔离配置中，`v0.1.4783` 曾加载本地示例并输出 Bun 标记。`magpie plugin list --json` 可能启动该 CLI 进程自己的宿主。 | 在目标常驻宿主中观察发送任务。临时进程参与时应保持单一写入者。 |
| Web | 示例插件已验证页面注册、资源返回及服务端读权限。按版本源码，打开带后端的插件页可以唤醒宿主。 | 在浏览器内分别验证页面桥握手、导航到服务页、诊断访问，以及页面关闭后的后台行为。 |
| Windows 桌面 | 页面桥提供普通 Options 操作，基线桥的服务入口为空。登录启动 Magpie 与发送定时器开始运行是两个观察点。 | 用桌面实际验证配置读写、提示、冷启动、重载、休眠恢复及所声明的无人值守条件。 |

示例的隔离目录、使用命令和观测记录见[Magpie 插件开发指南](Magpie插件开发指南.md)。宿主启动可追溯到[打开插件页的实现](https://github.com/yetone/magpie/blob/v0.1.4783/internal/gui/pluginpage.go)。

## 升级时怎样复核

1. 用 `magpie --version` 确认要支持的目标版本，记录运行方式与包版本。先从[官方插件指南](https://usemagpie.ai/docs/plugins)定位接口，再查目标标签下的实现、版本说明及与基线的差异。
2. 按变更选择兼容面。宿主变更查入口签名、Options、重载与所有权。页面变更查服务代理和桥权限。协议变更查源游标、身份与筛选绑定、字段校验及回执语义。
3. 在能观察该差异的最小隔离环境复验。记录版本、操作、实际结果和待验形态。完成后更新受影响的接口说明及[验收记录](08-开发阶段与验收计划.md)。

## 可复用的资料

- 网关、账本、游标和宿主的行为以选定标签的官方仓库为准。[yetone/magpie](https://github.com/yetone/magpie)
- 单向发送、重试与回填可参考现有上报插件。该项目直接读取 `usage.jsonl`，本项目的源客户端使用公开游标 API，双端兼容性需自行验收。[Lemonawa/magpie-usage-reporter](https://github.com/Lemonawa/magpie-usage-reporter)
- 看板、日报和 Webhook 可参考社区实现，首版功能范围见[插件定位与功能规格](01-插件定位与功能规格.md)。[lucklyduck/magpie-usage-reporter](https://github.com/lucklyduck/magpie-usage-reporter)
- 本机用量 API 请求与诊断输出可参考社区插件。[songouyang/magpie-usage-hachimo](https://github.com/songouyang/magpie-usage-hachimo)
