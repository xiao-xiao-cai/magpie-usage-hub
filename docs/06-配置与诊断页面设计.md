# 配置与诊断页面设计

管理员从中心 Magpie Web 的 **Magpie Usage Hub** 开始查询。工具栏的「配置」打开来源管理，同级提供「中心设置」和「运行诊断」。返回看板时恢复进入配置前的查询条件。中心 Web 通过 `3493` 回环页面服务代理访问看板与管理页。[部署接入](07-部署接入与运行维护.md)

## Options 与宿主校验

| 字段 | 用途与规则 |
| --- | --- |
| `collectionMode` / `role` | 中心保存时写入 `otlp` 和 `center`。升级时宿主兼容已启用的 `push` 中心设置，沿用其网关、监听、端口和时区。 |
| `enabled` | 页面选项「启用中心本机采集与用量看板」。全新安装自动启用，显式保存停用时保持停用。 |
| `receiverEnabled` | 「启用其他来源的 OTLP 接收」。全新安装默认关闭。已启用的旧中心沿用接收设置。 |
| `requestTimeoutSec` | 单次中心本机网关请求超时，单位秒。整数 `1`–`120`，默认 `30`。 |
| `configRevision` | 保存时生成的 UUID，用于核对 Options 读回、宿主读取与后台采用。 |
| `centerGatewayUrl` | 中心本机网关的 HTTP(S) 根地址。新设置留空使用中心宿主的回环端口；显式地址使用回环 IP 字面量 `127.0.0.1` 或 `[::1]`。 |
| `ingestHost` / `ingestPort` | OTLP 监听 IP 字面量和 TCP 端口。默认 `127.0.0.1` 和 `3494`。端口范围 `1`–`65535`，须避开 `3493` 和中心本机网关端口。Linux 原生中心填写服务器的 WireGuard 地址。Docker 桥接中心在容器内监听，接收端口发布到宿主的 WireGuard 地址。 |
| `publicEndpoint` | 来源设备实际访问的 HTTP(S) 基础地址，供接入向导显示。Docker 容器监听与宿主发布分别填写。 |
| `timeZone` | 看板预设、日界和显示使用的 IANA 时区，默认 `Asia/Shanghai`。 |

中心设置按本机采集、远端接收和看板显示分组。页面读回 Options 后开放编辑。分段控件切换时自动保存，可用 Tab 聚焦、方向键选择。文本和数字字段改动后，离开字段或按 Enter 触发保存。校验通过后串行写入，读回确认后更新「本机采集」右侧的保存修订，并在页面底部短暂显示「已保存」。读取或写入失败时，页首提供对应的恢复操作并保留草稿。发生冲突时可载入最新设置，核对草稿后重试。后台采用情况可在「运行诊断」查看。[开发基线](02-开发基线与兼容性.md)

运行诊断在两张状态卡上方分别显示「中心服务」和「中心本机采集」，刷新入口位于中心服务标题行右侧。卡内展示运行状态、接收监听和时间。出现异常时在对应卡内提示，可展开「详细信息」查看排查建议。中心服务的详细信息还显示宿主读取和后台采用的修订。接收失败时，中心本机和已入库用量仍能查询。[故障处理](05-同步流程与故障恢复设计.md#故障处理)

静态入口等待 `magpie.ready`，进入同一实例的 `magpie.service` 根路径启动页面服务。宿主重载后，向导以 Options 读回、持锁宿主采用的同一修订及端口正在监听为接收就绪的依据。桌面入口在服务地址为空时保留中心设置，并指引使用同一实例的 Web。[宿主交接](05-同步流程与故障恢复设计.md#来源配置与宿主交接) · [页面代理](https://github.com/yetone/magpie/blob/v0.1.4950/internal/gui/pageservice.go#L136-L145)

## 来源管理

「用量来源」及其「刷新」「添加设备」操作位于列表卡上方。卡内用细分隔线组织各行，来源名称使用常规字重，每行同时显示状态、最近活动和查看或编辑入口。子页在页头提供返回入口，按来源状态、基本信息、上报凭据和设备接入显示适用的卡片。保存、令牌操作和同源重建在对应卡内反馈。返回来源列表时焦点回到原条目，有未保存草稿时先确认。

添加设备依次完成登记及中心监听确认、Windows 配置和首次上报核对。页面标题和刷新操作沿用配置分组样式，卡片上方的步骤提示用正文色标识当前步骤。新设备登记卡从「来源名称」开始。监听确认后，向导使用新管理会话接续。Windows 配置卡逐行列出原生选项，地址和请求头命令可同行复制。首次上报核对卡显示接收状态和可用的最近接收时间。

| 管理操作 | 页面表现 |
| --- | --- |
| 添加设备 | 输入名称和上报令牌的 SHA-256 摘要。首次添加同时填写监听和设备可访问地址。已登记的来源可以在同一向导步骤继续确认接收；后续设备复用已生效的设置。 |
| 确认接入 | 在 Windows 保存导出设置并产生新用量。中心首次接受有效用量后从「等待首次上报」转为「已收到用量」，显示「最近接收」。 |
| 修改名称或启停 | 沿用来源 ID。暂停期间保留已接收记录，重新启用后可接收后续事件。 |
| 轮换或撤销令牌 | 登记新摘要，在 Windows 更新原生导出请求头。页面显示「已收到新令牌上报，可撤销原令牌」后，撤销原令牌并提升已验证的新凭据。凭据可逐槽撤销，也可一并撤销。 |
| 查看历史来源 | 看到「历史来源」时可查迁移保留的明细。接入原生导出时登记新的 OTLP 来源。 |
| 确认中心本机重建 | 中心本机等待游标恢复时，核对回环网关后确认重建。重建完成前仍查询已发布的数据。 |
| 出现修订冲突 | 重新读取来源列表，核对其他窗口的改动，再提交草稿。 |

管理页通过 Magpie Web 页面代理访问，宿主校验管理令牌。修改成功后返回新修订和脱敏的凭据槽状态。Windows 原生设置持有上报令牌，中心保存摘要。[管理与查询接口](04-网关接口与用量数据规范.md#看板与管理接口) · [Windows 上报配置](07-部署接入与运行维护.md#windows-上报配置)

## 中心 Web 用量看板

概览、明细、来源管理、中心设置和运行诊断共用宿主内容区，宽屏上限为 1200 CSS 像素。配置分类在工具栏左侧，当前分类以中性圆角底色和正文色显示，返回看板在右侧。顶栏分类与卡外分组标题沿用原生设置的小字号、字重和字距。中心设置和运行诊断的分组标题用弱化文字，位于对应圆角卡片上方。卡内由细分隔线划分设置行，说明在左侧，控件和状态值靠右。窄屏按内容宽度换行，输入框移到对应标签下方，来源行的操作仍靠右。明细范围、表格和分页位于同一张卡片，宽表格在表格区域内横向滚动。

进入看板默认为近 7 天、全部来源、网关。可选今天、近 30 天或自定义起止，切换「网关」「会话」「全部分项」。看板按设置的时区显示当地时间，采用 Magpie「用量」的日期和时钟格式。同日范围显示为 `11月27日 08:00 – 10:00`，跨日时两端均显示日期，非当年的端点带年份，端点有秒值时显示到秒。日轴显示 `11月27日`，小时轴显示 `08`，超过 24 小时的小时趋势同时显示月日。顶部「更新于」和当天明细显示 `08:00:00`，历史明细显示 `11月27日 08:00:00`，悬停可看完整日期与时间。自定义起止时间须带时区偏移或 `Z`，如 `2026-11-27T08:00:00+08:00`。点击「应用时间」或在时间输入框按 Enter 提交。[统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计)

- 趋势可选择自动、按小时或按日。自动在今天或不超过 24 小时的自定义区间使用小时。切换粒度沿用当前起止时间，超过 31 日的小时请求回退为日趋势，超过 366 日时仍可查看汇总和明细。
- 图表可用指针或左右方向键选择时段，查看输入、输出、次数、已计价费用及缺价。点「查看此时段明细」或按 Enter，翻页沿用该桶的开始与结束，回到概览恢复原周期和粒度。
- 趋势、来源卡片和模型排行共用 Token、次数和费用选择。每个来源用独立卡片显示当前指标、辅助数值、迷你趋势和占比，依内容宽度排为三列、两列或单列。点卡筛选，再点取消，焦点留在该卡。模型排行用一张卡片组织模型行，点模型进入明细，点「细项」在行内展开输入、输出、缓存、推理用量和缺价记录。
- 来源占比以所选时段与口径下全部来源为分母，模型占比使用当前来源筛选的合计。费用占比只用已计价金额，缺价单列，分母为零时显示 `—`。
- 用量采用 Magpie 原生「用量」的数字格式。默认缩写为 `1.0K`、`1.2M`、`1.20B`。简体中文启用宿主「万／亿」偏好时显示 `12.3 万`、`1.23 亿`，繁体中文使用 `萬`、`億`。顶部计量次数显示整数，占比取整。缩写后的主要数值可通过悬停或键盘焦点查看完整值。明细用时按 `850 毫秒`、`1.5 秒`、`12 秒` 显示。
- 金额使用 Magpie 设置的合计币种，覆盖概览、趋势、来源、模型和明细。「按供应商币种」时也使用合计币种。费用按原生符号和精度显示，例如 `$12.30`、`¥12.30`、`¥0.125`、`¥0.00012`。缺价条数单独显示，全部缺价时金额显示 `—`。
- 看板进入时经宿主页面桥的 `usage:day` 权限读取合计币种与汇率，经有查询令牌的页面服务读取该宿主配置中的 `chineseUnits` 布尔值。返回标签页时重读两项偏好。汇率缺失时金额显示美元，数字缩写仍按宿主的独立设置显示。

首次仅有中心时，看板提示「配置来源」；已有设备或历史来源时直接显示来源用量。刷新失败保留同一查询范围的上次成功结果，并标明成功读取时间。来源的运行状态在配置页可查。OTLP 的「最近接收」指最近一次提交有效用量批次的时间，明细按原调用时间展示。中心本机重建时继续查询已发布的历史。[故障处理](05-同步流程与故障恢复设计.md#故障处理)
