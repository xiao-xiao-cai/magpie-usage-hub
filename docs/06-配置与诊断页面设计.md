# 配置与诊断页面设计

管理员在 **Magpie Usage Hub** 插件页保存角色与连接设置，在同一实例的 Magpie Web 核对后台状态。Windows 桌面和 Web 使用同一配置页。`0.4.0` 托管试用的采集范围、启停和间隔由中心 Web 的「来源管理」设置。旧版本的配置步骤见[原生上报配置与回填](07-部署接入与运行维护.md#第三阶段配置与回填)和[连续同步 Options 示例](07-部署接入与运行维护.md#第二阶段连续同步配置)。

## Options 与宿主校验

| 配置项 | 用途、取值与校验 | 保存后的处理 |
| --- | --- | --- |
| `role`、`enabled` | `source` 采集并上报，`center` 接收并汇总。默认停用。切换角色会清除启用勾选，核对该角色设置后再启用并保存。 | 新宿主读取已保存的完整 Options。停用以旧任务退出为准。 |
| `requestTimeoutSec` | 单次 HTTP 请求超时，默认 30 秒，取 1–120 范围内的整数秒。 | 来源超时按退避规则处理，中心看板可保留已读取的分项。 |

### 托管来源设置

在「部署角色」选择「来源：采集并上报」，在「来源接入方式」选择「中心管理（一次配对）」。新来源配置默认采用该接入方式。勾选「启用当前角色」并「保存设置」后，后台才可配对。

| Options 字段 | 用途、取值与校验 |
| --- | --- |
| `mode` | 托管模式保存为 `managed`。 |
| `sourceGatewayUrl` | 「本机源网关」，本机回环 HTTP 或 HTTPS 根地址，主机为 `127.0.0.1` 或 `[::1]`。例如 `http://127.0.0.1:3425`。宿主核对回环网关归属后读取用量。 |
| `centralGatewayUrl` | 「中心接收地址」，来源可访问的节点入口根地址，走受限 WireGuard 接收口或校验证书的 HTTPS 入口。须与源网关不同，该地址纳入进度绑定。 |
| `pairingCodeFile` | 「一次性配对码文件路径」，含中心签发配对码的受保护文本文件绝对路径。首次配对需要该文件，配对成功后由节点状态保存凭据，配对码文件可移除。 |

中心下发专用模型 Key ID、供应商 ID、启停和轮询间隔。后台首次启用时从 `now` 持久化游标。配置读回及节点就绪的检查见[试用接入](07-部署接入与运行维护.md#登记来源并对账)。

### 手工来源设置

手工配置使用 `mode: "continuous"`，沿用已保存的来源绑定。`sourceGatewayUrl` 为本机回环网关，`centralGatewayUrl` 为原生网关或 Hub 接收监听，按实际写入目标填写。另需设置下列项目。

| 配置项 | 用途、取值与校验 | 保存后的处理 |
| --- | --- | --- |
| `sourceCallerKeyId` | 专用来源模型 Key 的 ID，启用时必填。 | 首次读取、日常续读和回填均使用同一 Key ID。 |
| `sourceProviderId` | 账本中的本机供应商 ID，显式启用 `source` 时必填。使用实际 ID，最多 256 个字符，不含空白或控制字符。 | 来源游标读页与回填同时按该供应商和专用 Key 筛选。供应商 ID 纳入持久绑定。 |
| `centralKeyFile` | 宿主上受保护的单个上报令牌文件的绝对路径。Windows ACL 仅授权宿主账号及必要管理员。 | 留空沿用已配置的路径。页面和诊断显示配置状态，Bun 发送时读取文件。 |
| `initialMode` | 默认「从现在开始」（`now`），采集初始游标之后的记录。另可显式选择「读取可见历史」（`start`），读取同一筛选范围内的历史。 | 首次模式写入状态绑定。再次运行从持久游标续读。 |
| `pollIntervalSec` | 正常轮询间隔，默认 60 秒。取 5–900 范围内的整数秒。 | 由取得任务所有权的调度器在每轮结束后采用。 |

旧版无 `role` 和供应商的原生上报配置仍可读取。手工 Hub 试用在 `trial/` 保存自己的身份与游标，中心按其来源 UUID 登记接收令牌。切换到托管来源前按[试用步骤](07-部署接入与运行维护.md#登记来源并对账)保存原绑定供回退。

### 中心设置

| 配置项 | 用途、取值与校验 | 保存后的处理 |
| --- | --- | --- |
| `centerGatewayUrl` | 同一中心宿主内的 Magpie 原生网关 HTTP 或 HTTPS 根地址，主机为 `127.0.0.1` 或 `[::1]`。 | 核对网关归属后取得任务所有权；看板通过该地址回环读取中心本机用量。 |
| `ingestHost` | 默认 `127.0.0.1`。从容器接收外部来源时显式选择 `0.0.0.0`，宿主侧只向已授权的专用网络发布接收端口。 | 取得锁后绑定 Hub 专用监听。Magpie 原生网关与页面服务端口各自保留。 |
| `ingestPort` | 默认 `3494`，为 1–65535 的整数。不得与中心网关或页面服务 `3493` 重用。 | 监听就绪后，来源将其可达的发布地址或对应 HTTPS 入口填为 `centralGatewayUrl`。 |
| `ingestKeyFile` | 可选，兼容手工登记的旧 Hub 来源。填写受保护的 JSON 凭据文件绝对路径，按 `sourceInstanceId` 配置唯一的 `key`。格式见[接收契约](04-网关接口与用量数据规范.md#批次与回执)。 | 托管来源凭据经配对登记。使用旧文件凭据时，配置变更后按来源验证续传。 |

## 读取、保存与生效

静态配置页由 `magpie.page.file` 声明。等 `magpie.ready` 后使用原生 `magpie.options.get()` 和 `.set()`。初次打开先读取已保存设置，失败后可按「重新读取」。Web 从同源的 `magpie.service` 提供来源的「打开运行诊断」或已启用中心的「打开用量看板」。Windows 桌面桥的服务地址为空，配置页提示改用同一实例的 Web 管理入口。

1. 保存前，配置页重新读取完整 Options，按页内字段和修订号核对编辑时的基线。检测到改动时列出差异字段，可通过「载入最新设置并保留草稿」更新基线，再核对后保存。
2. 页面将当前角色的设置合入最新完整对象，保留其他选项，并生成新的 `configRevision`。来源绑定未变时保留已提交的回填请求；绑定变化时清除 Options 中的旧请求，已持久化的历史保留在原状态目录。写入后读回完整对象，与提交相符才显示「已保存」和保存修订。写入失败保留草稿。读回失败时按「重新读取」核对本次提交，读回不一致时先查看差异。较早的刷新结果不会覆盖较新的结果或后续草稿。
3. 「已保存」只确认 Options 读回。来源 Web 诊断从配置页接收预期修订；核对宿主读取和任务采用的修订，首次同步另要确认游标已落盘。中心在看板的「后台诊断」核对保存修订和「中心接收就绪」。停用以旧宿主退出为准。首次配置或从旧版升级时，保存一次设置生成修订。

页面桥提供整对象读写，读、比较、写和读回分属多次调用，并发会话仍可能在读取与写入之间保存。操作时使用一个管理会话，发现差异后重读并核对草稿。Magpie `v0.1.4799` 要求两次写入至少间隔一秒，过快时返回 `429`，页面保留草稿。[Options 写入实现](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gui/pluginpage.go#L577-L637)

## Web 运行诊断

从来源的 Web 管理入口打开插件页并选择「打开运行诊断」。Bun 的诊断服务在 `127.0.0.1:3493` 提供静态资源和只读 `GET /api/status`，由 Magpie 代理到当前插件页入口。服务页通过相对路径 `api/status` 取得状态，每 10 秒在页面可见时刷新，也可手动「刷新」。重启后从配置页重新打开诊断，使用当前代理地址。

| 页面显示 | 含义与操作 |
| --- | --- |
| 后台状态和修订 | 等待上一宿主交接时，稍后刷新并核对采用的修订。已阻塞或正在退避时，看失败阶段、受控错误码、HTTP 状态和下次重试时间。 |
| 配对、暂停或来源就绪 | 等待配对时核对中心节点入口及临时配对码文件。暂停时节点仍读取配置，保持已确认游标。首次 `now` 游标持久化后才显示就绪。 |
| 最近尝试、最近整页确认 | 用两个时间区分正在尝试和已持久确认。空页也可确认。新宿主可读回确认时间，最近一页的摘要由本次宿主生成。 |
| 最近一页 | 显示日常同步或回填、确认数与其中的去重数，以及源流是否还有后续页。确认数为 `accepted + skipped`。源流还有后续页用于判断积压迹象。 |
| 回填进度 | 显示已受理的活动任务或最近的相关结果、时间边界、累计确认页数和条数。已拒绝或已中止时查看受控原因，核对后重新提交。 |
| 上报凭据文件 | 「已配置」代表 Options 已保存文件路径。文件不可读或中心拒绝上报时，按失败阶段检查宿主读权限和上报 Key 权限。 |
| 诊断暂时不可读或修订尚未匹配 | 重新从配置页打开诊断，检查宿主日志中的 `diagnostic_unavailable`。端口占用记录为 `diagnostic_port_in_use`。诊断监听独立重试，同时后台任务按自身状态运行。 |

状态响应使用 `Cache-Control: no-store`。页面以文本展示运行状态、计数、时间和受控错误码，诊断接口不返回凭据、文件路径、Key ID、账号标识、游标或原始异常。配置与回填提交使用 Magpie Options 桥。[管理入口与端口维护](07-部署接入与运行维护.md#第三阶段配置与回填)

## 中心 Web 用量看板

在中心 Magpie Web 的插件页启用中心并保存，选择「打开用量看板」。入口由当前 `magpie.service` 派生，重开宿主后从配置页重新进入。看板支持今天、近 7 天、近 30 天，按中心时区展示统计起点和原调用时间。页面首次打开、切换范围或点击「刷新」时读取数据。

| 页面显示 | 含义与操作 |
| --- | --- |
| 合计、中心本机、上报合计和单个来源 | 中心本机分为网关和直连。上报按来源 UUID 分组，托管来源显示登记名称。分项显示计量尝试、Token、缓存、已知估算费用和缺价计数。 |
| 用量明细 | 可选择中心网关、中心直连、所有上报来源或一个来源，按页查看。上报明细的来源 UUID 和 `rid` 可用于对账。 |
| 分项暂不可用、合计待确认 | 当前读数不完整，仍可查看已读分项。访问「后台诊断」检查监听状态，确认中心原生网关和 Hub 账本可读之后刷新。 |
| 本次读取失败 | 同一统计范围可暂存最近读取结果，并显示其时间；手动刷新重试。 |

看板从 Magpie 页面服务代理读取用量。管理员使用同一 Web 入口管理来源，节点在专用端口配对、读配置和上报。[查询和统计口径](04-网关接口与用量数据规范.md#怎样解释中心统计)

## 来源管理

在中心「用量看板」打开「来源管理」。选「添加来源」，填写来源名称、专用测试 Key ID、供应商 ID 和轮询间隔。间隔为 5–900 秒的整数，表单默认 60 秒。勾选「创建后启用采集」可在配对后立即建立 `now` 游标，留空则以暂停状态接入。选择「添加并生成配对码」，通过「显示配对码」读取 15 分钟内有效的单次配对码。尚未配对的来源可重新生成配对码。

已登记的来源可用「设置」暂停、恢复或调整间隔，节点下轮读取设置时采用。采集条件与当前游标绑定，调整 Key ID 或供应商 ID 时创建新来源。来源列表的「最近联系」记录中心上次成功处理配置请求的时间，「最近入账」记录上次接收新记录的时间。配对完成、来源游标就绪和中心收到第一条记录可分别核对。[变更采集范围与状态核对](07-部署接入与运行维护.md#管理已配对的来源)

重启后通过中心插件页重新进入当前代理地址。遇到设置已更新的提示时，刷新来源列表并核对后再保存。[管理页面接口](04-网关接口与用量数据规范.md#管理页面接口)

## 提交与跟踪回填

使用手工配置的连续同步时，先保存完整的来源启用设置并确认已有日常同步进度。在「向原中心回填」选择补齐指定时间段或恢复已过期或重置的游标。用当前浏览器或桌面的本地时区填写时间。起点最晚为当前时间。指定时间段的截止须晚于起点且最晚为当前时间。按「核对回填范围」，核对原来源网关、专用测试 Key ID、适用的供应商 ID、原中心、首次起点及以 UTC 显示的回填时间，再按「确认并提交」。

「回填请求已保存」表示 Options 已读回。去 Web 诊断确认请求受理、运行和结果。需要撤回时，使用「撤回待受理请求」，再确认宿主已读取新设置和请求的当前状态。已经受理的任务持久保存，停用同步可在宿主交接后暂停，恢复原设置并启用后续跑。首次使用时如遇 `recovery_no_checkpoint`，撤回请求并等待日常同步首次确认。诊断出现已拒绝或已中止时，先核对错误原因和仍可读的历史，再重新确认后提交。[受理条件和故障恢复](05-同步流程与故障恢复设计.md#向原中心回填)
