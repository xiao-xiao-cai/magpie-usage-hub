# 配置与诊断页面设计

`0.3.0` 候选包在来源 Magpie 的 **Magpie Usage Hub** 插件页提供同步配置与回填申请。Windows 桌面和 Web 使用同一配置页。需要核对后台采用的设置或查看回填进度时，打开同一来源的 Magpie Web 管理页。[第三阶段操作步骤](07-部署接入与运行维护.md#第三阶段配置与回填) · [第二阶段原生 Options](07-部署接入与运行维护.md#第二阶段连续同步配置)

## Options 与宿主校验

| 配置项 | 用途、取值与校验 | 保存后的处理 |
| --- | --- | --- |
| `enabled`、`mode` | 默认停用。勾选「启用连续同步」并保存时写入 `enabled: true` 和 `mode: "continuous"`。 | 新宿主读取已保存的完整 Options。停用以旧任务退出为准。 |
| `sourceGatewayUrl` | 本机源网关的 HTTP 或 HTTPS 根地址，主机为 `127.0.0.1` 或 `[::1]`。例如 `http://127.0.0.1:3425`，端口以实际监听为准。 | 宿主核对回环网关归属和现有来源绑定，通过后才能使用已保存游标。 |
| `sourceCallerKeyId` | 专用来源模型 Key 的 ID，启用时必填。 | 首次读取、日常续读和回填均使用同一 Key ID。 |
| `centralGatewayUrl` | 与源网关不同的中心 HTTP 或 HTTPS 根地址，例如 `https://magpie.example.com`。HTTPS 必须验证证书，上报遇到重定向即停止，避免凭据转发。 | 中心属于进度绑定。已有进度时要迁移中心，先确认目标和历史范围。 |
| `centralKeyFile` | 宿主上受保护的上报 Key 文件的绝对路径。Windows ACL 仅授权宿主账号及必要管理员。 | 输入留空时沿用已配置的路径。配置页和诊断显示配置状态。Bun 在有行需要发送时读取文件，配置状态仅表示已填写路径。 |
| `initialMode` | 默认「从现在开始」（`now`），采集初始游标之后的记录。选择「读取可见历史」（`start`）时读取该 Key 的可见历史。 | 首次模式写入状态绑定。再次运行从持久游标续读。 |
| `pollIntervalSec` | 正常轮询间隔，默认 60 秒。取 5–900 范围内的整数秒。 | 由取得任务所有权的调度器在每轮结束后采用。 |
| `requestTimeoutSec` | 单次 HTTP 请求超时，默认 30 秒。取 1–120 范围内的整数秒。 | 超时进入退避重试。与正常轮询间隔分别配置。 |

## 读取、保存与生效

静态配置页由 `magpie.page.file` 声明。等 `magpie.ready` 后使用原生 `magpie.options.get()` 和 `.set()`。初次打开先读取已保存设置，失败后可按「重新读取」。Web 从同源的 `magpie.service` 提供「打开运行诊断」入口。Windows 桌面桥的服务地址为空，配置页提示使用同一来源的 Web 管理入口。

1. 保存前，配置页重新读取完整 Options，按页内字段和修订号核对编辑时的基线。检测到改动时列出差异字段，可通过「载入最新设置并保留草稿」更新基线，再核对后保存。
2. 页面把本次修改合入最新完整对象，保留其他选项，并生成新的 `configRevision`。提交期间禁用重复提交。写入后读回完整对象，与提交相符才显示「已保存」和保存修订。写入失败保留草稿。读回失败时按「重新读取」核对本次提交，读回不一致时先查看差异。较早的刷新结果不会覆盖较新的结果或后续草稿。
3. 「已保存」只确认 Options 读回。Web 诊断在宿主读取与配置页保存修订一致后展示状态。「同步任务采用的修订」表示启用任务已取得锁并核对状态绑定。停用修订由宿主读取，任务停下以旧宿主退出为准。首次配置或从旧版升级时，保存一次设置即可生成修订并打开诊断。

页面桥提供整对象读写，读、比较、写和读回分属多次调用，并发会话仍可能在读取与写入之间保存。操作时使用一个管理会话，发现差异后重读并核对草稿。Magpie `v0.1.4799` 要求两次写入至少间隔一秒，过快时返回 `429`，页面保留草稿。[Options 写入实现](https://github.com/yetone/magpie/blob/v0.1.4799/internal/gui/pluginpage.go#L577-L637)

## Web 运行诊断

从来源的 Web 管理入口打开插件页并选择「打开运行诊断」。Bun 的诊断服务在 `127.0.0.1:3493` 提供静态资源和只读 `GET /api/status`，由 Magpie 代理到当前插件页入口。服务页通过相对路径 `api/status` 取得状态，每 10 秒在页面可见时刷新，也可手动「刷新」。重启后从配置页重新打开诊断，使用当前代理地址。

| 页面显示 | 含义与操作 |
| --- | --- |
| 后台状态和修订 | 等待上一宿主交接时，稍后刷新并核对采用的修订。已阻塞或正在退避时，看失败阶段、受控错误码、HTTP 状态和下次重试时间。 |
| 最近尝试、最近整页确认 | 用两个时间区分正在尝试和已持久确认。空页也可确认。新宿主可读回确认时间，最近一页的摘要由本次宿主生成。 |
| 最近一页 | 显示日常同步或回填、确认数与其中的去重数，以及源流是否还有后续页。确认数为 `accepted + skipped`。源流还有后续页用于判断积压迹象。 |
| 回填进度 | 显示已受理的活动任务或最近的相关结果、时间边界、累计确认页数和条数。已拒绝或已中止时查看受控原因，核对后重新提交。 |
| 上报凭据文件 | 「已配置」代表 Options 已保存文件路径。文件不可读或中心拒绝上报时，按失败阶段检查宿主读权限和上报 Key 权限。 |
| 诊断暂时不可读或修订尚未匹配 | 重新从配置页打开诊断，检查宿主日志中的 `diagnostic_unavailable`。端口占用记录为 `diagnostic_port_in_use`。诊断监听独立重试，同时后台任务按自身状态运行。 |

状态响应使用 `Cache-Control: no-store`。页面以文本展示运行状态、计数、时间和受控错误码，诊断接口不返回凭据、文件路径、Key ID、账号标识、游标或原始异常。配置与回填提交使用 Magpie Options 桥。[管理入口与端口维护](07-部署接入与运行维护.md#第三阶段配置与回填)

## 提交与跟踪回填

先保存完整的启用设置并确认已有日常同步进度。在「向原中心回填」选择补齐指定时间段或恢复已过期或重置的游标。用当前浏览器或桌面的本地时区填写时间。起点最晚为当前时间。指定时间段的截止须晚于起点且最晚为当前时间。按「核对回填范围」，核对原来源网关、专用测试 Key ID、原中心、首次起点及以 UTC 显示的回填时间，再按「确认并提交」。

「回填请求已保存」表示 Options 已读回。去 Web 诊断确认请求受理、运行和结果。需要撤回时，使用「撤回待受理请求」，再确认宿主已读取新设置和请求的当前状态。已经受理的任务持久保存，停用同步可在宿主交接后暂停，恢复原设置并启用后续跑。首次使用时如遇 `recovery_no_checkpoint`，撤回请求并等待日常同步首次确认。诊断出现已拒绝或已中止时，先核对错误原因和仍可读的历史，再重新确认后提交。[受理条件和故障恢复](05-同步流程与故障恢复设计.md#向原中心回填)
